# 발표 노트 — 기술 면접관 10분 기준

슬라이드: [발표자료.html](발표자료.html) (브라우저로 열면 바로 발표 가능)

- `←` `→` 슬라이드 이동 · `F` 전체화면 · `P` 인쇄(각 슬라이드가 한 페이지 → PDF)
- **외부 요청이 없다.** CSS·JS 전부 인라인이라 오프라인·와이파이 없는 면접장에서도 열린다
- URL 해시로 특정 슬라이드 직행 가능 (`발표자료.html#8`)

## 시간 배분 (총 10분)

| # | 슬라이드 | 시간 | 이 슬라이드의 목적 |
|---|---|---:|---|
| 1 | 표지 | 0:15 | 한 문장 정의 |
| 2 | 한 장 요약 | 0:45 | 규모 감각 + **"기각한 것도 가져왔다"고 예고** |
| 3 | 설계 목표 | 1:00 | 왜 라우팅인가 — 문제의식 |
| 4 | 유형별 파이프라인 | 0:45 | 설계 목표가 LLM 호출 수로 나타남 |
| 5 | 아키텍처 | 0:45 | 전체 그림, 빠르게 |
| 6 | 측정된 개선 | 0:45 | 수치는 훑고 지나간다 — 여기서 시간 쓰지 말 것 |
| 7 | **기각한 것** | 0:45 | 이 발표의 전환점 |
| 8 | 사례 1 — 임계값 | 1:15 | **깊이 파는 곳 ①** |
| 9 | 사례 2 — 상관/인과 | 1:15 | **깊이 파는 곳 ②** |
| 10 | 사례 3 — 검사가 틀린다 | 1:00 | 깊이 파는 곳 ③ (시간 부족하면 여기를 줄인다) |
| 11 | 부하테스트 | 0:45 | 오버셀 0 + 병목 이동 |
| 12 | 멀티테넌시·보안 | 0:35 | 데모 한계를 **먼저** 밝힌다 |
| 13 | 한계 | 0:30 | 빠르게, 방어적으로 굴지 말 것 |
| 14 | 마무리 | 0:30 | 습관 세 가지 |

## 슬라이드별 말할 것

**2 — 한 장 요약**
> "기능을 다 보여드리기엔 10분이 짧아서, **주장에 근거가 붙어 있는지**를 중심으로
> 가져왔습니다. 그래서 개선한 것뿐 아니라 **해보고 접은 것**도 같이 있습니다."

이 한마디가 뒤의 슬라이드 7~10을 정당화한다. 빠뜨리지 말 것.

**3 — 설계 목표**
"LLM을 안 쓴다"가 아니라 **"유형마다 다르게 쓴다"**임을 분명히. 캐시가 라우터보다
앞에 있는 이유를 물으면 — 어떤 분기든 같은 질문이면 일을 안 하는 게 가장 싸기 때문.

**6 — 측정된 개선**
읽지 말 것. "이런 것들을 쟀다" 정도로 넘기고 7번으로. **숫자 낭독은 시간만 먹는다.**

**8 — 사례 1 (임계값)**
핵심 문장: **"같은 분할을 반복 실행하면 노이즈를 재는 것이지 일반화를 재는 게 아니다."**
전수 열거가 추가 API 호출 없이 공짜였다는 점을 꼭 말할 것 — 비용 대비 효과가 크다.

**9 — 사례 2 (상관/인과)**
좌우 두 표를 손으로 짚으며. 핵심 문장: **"부하 중 wall-time은 그 단계의 작업량이
아니다."** 10ms 타이머 검증이 싸다는 것도 — 방법론을 물어보기 좋은 지점이다.

**10 — 사례 3 (검사가 틀린다)**
가장 최근 것이고 **내가 건 판정선이 틀린 사례**라 솔직함이 드러난다.
"고쳐서 통과시키지 않았다"를 반드시 말할 것.

**12 — 보안**
데모 한계를 **질문받기 전에 먼저** 말한다. 방어처럼 들리지 않는다.

**14 — 마무리**
세 문장을 그대로 읽지 말고 각각 앞의 사례를 가리키며 말한다.

## 예상 질문과 답

| 질문 | 답의 뼈대 |
|---|---|
| 왜 Oracle이 아니라 PostgreSQL? | 라이선스·운영 단순성 + 직전 프로젝트가 Oracle이라 **경험 분산**. 의도적 선택이고 ADR에 있다 |
| Isolation Forest가 더 흔하지 않나? | 맞다. **재구성 오차의 설명 가능성** 때문에 오토인코더를 택했다 — 피처별 기여도로 GM에게 근거를 보여줄 수 있다. 대신 신규 계정은 규칙이 더 낫고 그것도 적어뒀다 |
| 합성 데이터라 의미가 있나? | 없다고 본다, **단독으로는.** 그래서 naive 기준선을 항상 같이 출력한다. 판단 기준은 MAPE가 아니라 "기준선을 이겼는가" |
| 왜 MCP를 썼나? | 내부 도구를 표준 인터페이스로 노출하는 연습. **외부 커넥터는 의도적으로 제외**했다 — 서드파티 인증·파싱 비용을 안 지려고 |
| 4 OCPU면 실서비스가 되나? | 안 된다. 그래서 상시 기동을 피하고 지연 로딩·프로파일 opt-in을 넣었다. 수치도 **같은 박스에서 부하를 걸었으니 보수적**이라고 적어뒀다 |
| 테스트가 적지 않나? | **적다.** AI는 결정론적 단위에만 한정했고(모델 품질은 홀드아웃 리포트가 판단), 백엔드 도메인 규칙은 여전히 수동이다. 로드맵에 남아 있다 |
| 혼자 한 것인가 | 설계·구현·측정 전부. AI 코딩 도구를 쓰되 **판정 기준을 먼저 정하고 측정으로 검증**하는 방식으로 진행했다 |

## 준비물

- 브라우저 하나 (오프라인 가능)
- 백업: `P`로 PDF 내보내 둘 것 — 발표 직전 노트북이 바뀌는 경우 대비
- 데모를 같이 한다면 **워밍업을 먼저** 돌릴 것. 첫 요청은 모델 지연 로딩으로
  20초 가까이 걸린다
