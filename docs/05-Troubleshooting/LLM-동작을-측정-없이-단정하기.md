# LLM의 동작을 측정 없이 단정했다 — 다섯 건

> 2026-07-31 재작성 결정성 작업에서 세 가지가 걸렸는데, 증상은 다르지만 원인이
> 하나다: **LLM이 왜 그렇게 동작하는지를 재보지 않고 결론지었다.** 셋 다
> 그럴듯했고, 셋 다 틀렸거나 과장이었다. 이 프로젝트는 LLM 위에 파이프라인을
> 얹고 있어서 재발 조건이 상시 존재한다.
>
> **2026-08-07 도메인 게이트 작업에서 두 건이 더 나왔다**(사례 4·5). 앞의 셋이
> "왜 그런가"를 단정한 것이라면 뒤의 둘은 **"이렇게 고치면 나아질 것"을**
> 단정한 것이다. 둘 다 그럴듯했고 둘 다 나빠졌다.

## 사례 1: 미설정 파라미터를 "모델의 근본 특성"으로 진단했다

### 문제

같은 질의가 실행마다 다르게 재작성되는 현상을 여러 라운드에 걸쳐
**"LLM 질의 재작성의 비결정성"** 으로 서술했다. ADR-0014는 그걸 근거로
리랭커 하한을 기각했고, ADR-0016은 0건 응답 캐시 금지의 근거로 삼았다.

### 발생 원인

`temperature`를 API에 **한 번도 안 넘겼다.**

```python
kwargs = {"model": self._model, "messages": messages}   # temperature 없음
```

생략하면 OpenAI Chat Completions는 **기본값 1.0**을 쓴다. 최대 샘플링 온도로
6개 Phase를 돌렸다.

**아무도 이걸 못 본 이유**: 코드가 정상으로 보였고 에러도 없었다.
**없는 파라미터는 눈에 띄지 않는다.** 있는 코드는 읽히지만 없는 코드는 안
읽힌다. "LLM은 원래 그렇다"는 설명이 그럴듯해서 더 안 봤다.

### 해결

`temperature=0`을 **명시적으로** 실어 보낸다. 토큰집합 모드 일치율
0.840 → 0.990, 불안정 질의 5/10 → 1/10. 검색 품질은 무변화.

`tests/test_llm_temperature.py`가 "값이 kwargs에 들어가는가"를 고정한다 —
이 결함은 다시 생겨도 조용할 것이기 때문이다.

## 사례 2: 관측하지 않은 것을 관측한 것에서 일반화했다

### 문제

ADR-0016이 0건 응답을 캐시하지 않는 이유 1로 **"판정 근거인 필터 추출이
비결정적이다"** 를 들었다.

### 발생 원인

**그건 측정이 아니라 추론이었다.** 실제로 관측한 건 재작성 *텍스트*의 변동
(`"검 소드 대검"` vs `"검 소드 대검 단검"`)이고, 거기서 "필터도 흔들릴
것"이라고 넘겨짚었다. 둘 다 같은 LLM 호출의 출력이니 자연스러운 추론처럼
보였다.

실측하니 **temperature 1.0에서도 필터는 10질의 × 10회 전부 동일**했다
(모드 일치율 1.000). 텍스트는 흔들리는데 필터는 안 흔들렸다 — 자유 서술
필드와 열거형 필드의 안정성이 다르다.

### 해결

이유 1의 강도를 낮추고 그 사실을 ADR-0016·0017 양쪽에 남겼다. **결정 자체는
유지**된다 — 이유 2(0건은 매물 하나만 등록돼도 거짓이 되는 가장 낡기 쉬운
답)가 독립적으로 서 있기 때문이다.

결정이 살아남은 건 **근거를 두 개 세워놨기 때문**이지 추론이 맞아서가 아니다.

## 사례 3: 타당해 보이는 프롬프트 한 줄이 정답률을 4배 낮췄다

### 문제

남은 오추출이 `불속성` ↔ `무속성` 혼동(한 글자 차이, 정반대 뜻)이라
프롬프트에 혼동 방지 문구를 넣었다.

> **`불속성`과 `무속성`을 혼동하지 마세요.** `불속성`은 불(화염) 속성이라
> "화염"이고, `무속성`은 속성이 아예 없다는 뜻이라 "무속성"입니다.

### 발생 원인

| | `"3만원 이하 불속성 검"` → `화염` |
|---|---|
| 추가 전 | **39/40 (97.5%)** |
| 추가 후 | **11/50 (22%)** |
| 되돌린 후 | **50/50** |

`무속성`을 눈에 띄게 언급한 것 자체가 모델을 그쪽으로 유도했다.
**"혼동하지 마라"고 말하는 행위가 혼동을 만들었다.**

### 해결

되돌렸다. 프롬프트 수정은 눈으로 판단하지 않고
`scripts/evaluate_rewrite_determinism.py`로 잰다.

### 이 사례가 특히 위험한 이유

문구 자체가 **누가 봐도 타당하다.** 코드 리뷰로 안 걸리고, 스모크 테스트로도
안 걸린다(가끔 틀리는 게 아니라 78%가 틀리는데도 "어쩌다 틀렸네"로 보인다).
측정 없이 넣었으면 0건 경로의 핵심 질의를 4배 악화시킨 채 배포했을 것이다.

## 사례 4: 한 호출에 일을 하나 더 얹었더니 **원래 하던 일이 망가졌다**

> 2026-08-07, ADR-0039. 위 셋과 같은 계열인데 **개입한 자리가 문구가 아니라
> 스키마**다.

### 문제

도메인 밖 질의(`"삼성전자 주식 어때?"`)를 거절해야 했다. `understand_query`가
이미 검색·시세 분기에서 도는 호출이라, **그 JSON 스키마에 `in_domain` 필드를
하나 더하면 LLM 호출이 안 는다.** 자연스러운 설계로 보였다.

### 발생 원인

호출을 안 늘린 대신 **추출 품질을 지불하고 있었다.**

| | 1회차 | 2회차 (문구 수정) |
|---|---|---|
| 필터 완전 일치 (대조군 대비) | -0.106 | -0.071 |
| **재작성 토큰집합 일치 (대조군 대비)** | **-0.234** | **-0.248** |

**문구를 고쳤더니 오거부는 29.9% → 13.4%로 절반이 됐는데 재작성 손실은 그대로
였다.** 그 대비가 원인을 지목한다 — 문구가 아니라 **출력 스키마가 늘어난 것
자체**다. 모델이 `in_domain`을 먼저 쓰고 나머지를 이어 쓰는 생성 궤적으로
바뀌었고, 재작성 텍스트는 BM25와 kNN 양쪽에 들어간다.

### 대조군이 없었으면 못 봤다

`temperature=0`이어도 같은 질의가 10건에 1건은 다르게 재작성된다(ADR-0017).
**신·구 일치율 0.89만 보면 프롬프트 탓인지 계측기 바닥인지 알 수 없다.**
구프롬프트를 두 번 태워 대조군(0.965 / 0.915)을 먼저 재놨기 때문에 델타가
의미를 가졌다.

### 해결

판정을 **별도 호출로 떼고 `asyncio.gather`로 병렬**로 던졌다. 추출 프롬프트를
아예 안 건드리므로 회귀가 **구조적으로 0**이다 — 측정으로 통과한 게 아니라
불가능해진 것이고, `tests/test_domain_gate.py::TestExtractionPromptStaysClean`이
되돌아오는 걸 막는다.

대가는 호출 1회 증가인데 둘 다 순수 I/O 대기라 **지연은 실측 0**이다(판정
636~900ms, 질의이해 1237~2769ms — 언제나 판정이 먼저 끝난다).

> **비용을 아끼려고 한 호출에 두 일을 시키면, 둘째가 첫째를 조용히 갉아먹는지
> 확인해야 한다.** 이 저장소는 "동의어 확장 + 필터 추출을 한 호출로"를 처음부터
> 설계 원칙으로 삼았다 — 그 원칙 자체는 유효하지만 **공짜가 아니라는 것**이
> 여기서 처음 측정됐다.

## 사례 5: 포함을 넓히려 넣은 열거가 **배제의 근거로** 쓰였다

> 같은 라운드. 이번엔 문구인데, 사례 3과 방향이 다르다.

### 문제

거절 게이트의 오거부가 4.13%까지 내려왔고 잔여가 **게임 은어·오타**였다
(`"폭창"`, `"55방각반"`, `"8강 롱검"` — 모델이 장비 이름인 줄 모른다). 그래서
취급 품목을 열거해줬다.

```
취급 품목: 검·둔기·창·활·지팡이 / 갑옷·방패·신발·로브·모자·각반 / …
```

동시에, 완화만 넣으면 공략 질문까지 통과할까 봐 금지 규칙도 넣었다.

```
- **물건이 아니라 플레이 방법**(공략·보스 잡는 법·스킬트리·레벨업)이면 NO입니다.
```

### 발생 원인

오거부가 **4.13% → 5.30%로 올라갔다.** 걸린 표본이 원인을 갈라줬다.

| 넣은 것 | 새로 잘린 것 |
|---|---|
| 취급 품목 목록 | `"고대 유물 조각 구합니다"`, `"수정으로 만든 마법 아이템 찾기"` — **목록에 없는 이름** |
| "플레이 방법은 NO" | `"스킬 쿨타임 줄이는 장신구"`, `"장비 강화 할 때 쓰는 아이템"` — `스킬`·`강화`라는 **낱말** |

둘 다 의도의 반대다.

- **열거는 포함을 넓히려고 넣었는데 모델이 "목록에 없으면 아니다"로 읽었다.**
  예시(example)와 정의(definition)의 차이를 모델이 지켜주지 않는다.
- **금지 규칙은 의미가 아니라 낱말에 걸린다.** 이건 이 저장소가 정규식에서 두 번
  겪은 실패([[검사-자체가-틀린-사례들]] 사례 16)가 **프롬프트에서 재연된 것**이다.

### 해결

둘 다 걷어내고 완화 두 개만 남겼다 → **0.59%**. 근거가 있었다: **다섯 번의
실행에서 미검출이 언제나 0/38**이었으므로, 가장 관대한 문구에서도 하나도 안
놓친다는 뜻이라 관대한 쪽으로 밀어도 안전했다.

### 네 가지를 한꺼번에 넣은 것도 잘못이다

품목 목록·성능 질문 완화·이름 완화·플레이 방법 금지를 **한 번에** 넣었다. 나빠진
건 알았지만 **어느 것 때문인지는 걸린 표본을 읽어서 추정한 것이지 측정한 게
아니다.** 프롬프트도 한 번에 하나씩 바꿔야 한다.

## 공통 원인과 판별법

다섯 사례 모두 **"LLM이 왜 그렇게 동작하는지에 대한 주장을 재보지 않고
했다"** 이다. 그런데 형태가 다르다.

| 사례 | 주장의 형태 | 실제 |
|---|---|---|
| 1 | 원인을 모델 탓으로 | 우리 쪽 설정 누락 |
| 2 | 관측한 것에서 일반화 | 일반화가 성립 안 함 |
| 3 | 개입이 도움이 될 것 | 4배 악화 |
| 4 | **일을 더 얹어도 원래 일은 그대로일 것** | 재작성 일치도 -0.248 |
| 5 | **예시를 주면 포함이 넓어질 것** | 배제의 근거가 됨 |

### 판별 순서

LLM이 이상하게 동작할 때 **이 순서로** 확인한다.

1. **요청 파라미터를 먼저 본다.** `temperature`, `top_p`, `max_tokens`, `seed`,
   `response_format` — 안 넘긴 게 있으면 그 API의 기본값이 무엇인지 확인한다.
   "안 넘겼다 = 무난한 값"이 아니다.
2. **"모델 특성"이라는 결론은 1번을 확인한 뒤에만 낸다.**
3. **관측한 축과 주장하는 축이 같은지 본다.** 텍스트가 흔들린 걸 봤다면
   텍스트에 대해서만 말한다. 필터도 흔들린다고 하려면 필터를 재야 한다.
4. **프롬프트 수정은 전후를 잰다.** n은 최소 30 — 5~10회로는 20%대 실패율도
   "어쩌다"로 보인다.
5. **비교에는 대조군을 붙인다.** 신·구 일치율만으로는 프롬프트 탓과 LLM 변동을
   가를 수 없다. **구프롬프트를 두 번 태워** 같은 프롬프트끼리의 일치율을 먼저
   재둔다(사례 4).
6. **한 번에 하나씩 바꾼다.** 여러 문구를 같이 넣으면 나빠진 건 알아도 무엇
   때문인지는 추정밖에 못 한다(사례 5).
7. **숫자만 보지 말고 걸린 표본을 읽는다.** 이 라운드에서 오거부의 *정체*가
   회차마다 바뀌었다 — 시세 질문 → 흐릿한 대상 → 게임 은어. 비율만 봤으면
   "프롬프트가 더 필요하다" 이상은 알 수 없었다.

### 체크리스트

- [ ] 이 LLM 호출이 넘기지 **않는** 파라미터는 무엇이고, 그 기본값은?
- [ ] "모델이 원래 그렇다"고 쓰기 전에 설정을 확인했는가?
- [ ] 내가 잰 것과 내가 주장하는 것이 같은 대상인가?
- [ ] 프롬프트를 고쳤다면 전후를 n≥30으로 쟀는가?
- [ ] **대조군(같은 프롬프트끼리의 일치율)을 재놨는가?** 없으면 델타의 크기를
      해석할 수 없다
- [ ] **이번에 바꾼 것이 하나인가?** 여럿이면 원인 지목은 추정이다
- [ ] **기존 호출에 일을 하나 더 얹었다면, 원래 하던 일을 다시 쟀는가?**
      출력 스키마가 늘어나는 것만으로 나머지 필드가 흔들린다(사례 4)
- [ ] 금지·열거 규칙을 넣었다면 **의도의 반대로 작동하지 않는지** 확인했는가?
      열거는 배제로, 금지어는 낱말 일치로 새어나간다(사례 5)
- [ ] 결론이 뒤집혔을 때 **결정까지 무너지는가**, 아니면 다른 근거가 있는가?
      (사례 2는 근거가 둘이라 살아남았다)
