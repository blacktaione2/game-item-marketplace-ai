# 신경망 분류기의 softmax 확신도로 "애매함"을 걸러낼 수 없다

## 문제

Phase 6 Intent Router의 핵심 설계는 "**애매하면 에이전트로 보낸다**"였다.
`"이거 적정가야?"`처럼 검색인지 시세예측인지 정해지지 않는 질의를 억지로 한
클래스로 확정하지 않고, 확신도가 낮으면 `compound`로 올려 에이전트가 도구를
스스로 고르게 하는 구조다.

구현은 단순했다 — `confidence < 0.70`이면 `compound`. 그런데 KoELECTRA를
학습시키고 나니 경계 발화 20건 중 **에스컬레이션이 0건**이 됐다.

```
경계 발화 20건 — 에이전트로 빠져야 정상
COMPOUND로 에스컬레이션: 0/20
  시세 문의 (classifier): 9
  FAQ/스몰토크 (classifier): 4
  아이템 검색 (classifier): 3
```

학습 **전**(모델 없이 룰만)에는 16/20이 에스컬레이션됐다. **모델을 붙였더니
설계 목표가 통째로 깨진 것이다.**

## 발생 원인

임계값을 올리면 될 것 같지만 아니었다. 확신도 분포를 재보니 원인이 드러났다.

| 구간 | n | 평균 | 중앙값 | 최소 |
|---|---|---|---|---|
| 평가셋 **정답** | 33 | 0.979 | 0.991 | 0.862 |
| 평가셋 **오답** | 27 | 0.905 | **0.978** | 0.503 |
| 경계 발화 | 20 | 0.958 | 0.991 | 0.618 |

**오답의 확신도 중앙값(0.978)이 정답(0.991)과 사실상 같다.** 확신도가 맞고
틀림에 대한 정보를 거의 담고 있지 않다는 뜻이고, 그러면 **어떤 임계값도
둘을 못 가른다.** 0.99로 올리면 오답과 함께 정답도 대부분 버린다.

개별 값을 보면 더 분명하다.

```
0.992  "이거 뭐야"      -> 시세 문의
0.992  "괜찮나요"       -> 시세 문의
0.992  "적당한거로"     -> 시세 문의
0.991  "이거 믿을만해?" -> FAQ/스몰토크
```

원인은 두 가지가 겹친 것이다.

1. **학습 손실을 0.013까지 떨어뜨렸다.** 420건짜리 작은 데이터셋을 30에폭
   돌리면 모델이 학습 데이터를 외우고, softmax가 거의 one-hot으로 수렴한다.
   과적합된 신경망이 과확신하는 것은 잘 알려진 현상이다.
2. **cross-entropy에는 "모르겠다"는 출력이 없다.** 5개 클래스 중 하나를
   반드시 고르게 훈련시켜 놓고 "확신 없으면 기권하라"를 기대한 것이다.
   모델은 애매함을 표현하는 법을 배운 적이 없다.

## 해결 방법

**확신도에서 애매함을 유도하지 않고, 애매함을 클래스로 직접 가르쳤다.**

1. **모호한 발화를 `compound`로 학습**시켰다. LLM으로 "무엇을 원하는지 특정할
   수 없는 짧고 모호한 발화" 108건을 생성해 `compound` 라벨로 넣었다.
   `compound`는 언어 형태가 아니라 **"도구를 특정할 수 없거나 여러 개
   필요하다"는 취할 행동**으로 정의되므로 의미상 모순이 없다.
   - 수작업 경계 평가셋은 홀드아웃이라 학습에 못 쓴다. 별도로 생성했고,
     생성분 중 1건이 홀드아웃과 겹쳐 자동으로 걸러졌다.
2. **레이블 스무딩 0.1**을 걸어 과확신을 완화했다.
3. 에폭을 30 → 20으로 줄였다(검증 정확도가 15에폭에 이미 평탄).

### 결과

| | 수정 전 | 수정 후 |
|---|---|---|
| 경계 발화 에스컬레이션 | **0/20** | **15/20** |
| 2단 라우터 홀드아웃 정확도 | 83.3% | **86.7%** |

남은 5건 중 4건은 룰이 확정한 것이라 분류기를 거치지 않는다. 그건 실행
단계에서 분기가 스스로 물러서는 방식으로 처리했다(대상을 특정 못 하면
에이전트로 에스컬레이션).

## 배운 점

**softmax 확신도는 확률이 아니다.** 이름과 형태가 확률처럼 생겼고 합이 1이라
그렇게 쓰고 싶어지지만, 교정(calibration)되지 않은 신경망의 출력은 "이만큼
확신한다"가 아니라 그냥 상대적 점수다. 특히 작은 데이터셋에 과적합시킨 모델은
틀릴 때도 0.99를 뱉는다.

그래서 **"확신도가 낮으면 ~한다"는 설계는 확신도가 교정되어 있다는 전제
위에서만 성립한다.** 그 전제를 확인하지 않고 임계값부터 정하면 이번처럼
기능이 조용히 죽는다 — 에러도 없고, 라우팅은 계속 되고, 정확도 지표도
그럭저럭 나온다. 경계 발화 에스컬레이션이라는 **별도 지표를 따로 재지
않았다면 못 잡았을 것이다.**

그리고 더 일반적인 교훈: **모델에게 기대하는 동작이 있으면 그 동작을 직접
가르치는 편이, 다른 출력에서 유도하는 것보다 낫다.** "애매함"을 확신도에서
뽑아내려다 실패했고, 클래스로 가르치자 바로 됐다.

### 재발 조건과 체크리스트

모델 출력의 확신도·점수를 **판단 기준으로 쓰는 모든 곳**에 해당한다.
이 프로젝트에는 이미 여러 곳에 있다 — Intent Router 임계값, 시맨틱 캐시
유사도 임계값, 이상탐지 재구성 오차 임계값, 리랭커 점수.

- [ ] 이 점수가 **교정되어 있다고 가정**하고 있지는 않은가?
- [ ] **맞은 경우와 틀린 경우의 점수 분포를 실제로 재봤는가?** 두 분포가
      겹치면 임계값으로는 못 가른다.
- [ ] 임계값이 하려는 일(기권·에스컬레이션·필터링)을 **별도 지표로 측정**하고
      있는가? 정확도만 보면 이 결함이 안 보인다.
- [ ] 학습 손실이 0에 가깝게 떨어졌는가? 그렇다면 과확신을 의심하고
      레이블 스무딩·조기 종료·온도 스케일링을 검토한다.
- [ ] 모델에게 원하는 동작을 **클래스나 출력으로 직접 가르칠 수 있는가?**
      다른 출력에서 유도하는 것보다 대개 낫다.

### 남은 한계

레이블 스무딩은 **완화**이지 교정이 아니다. 확신도가 여전히 신뢰할 수 있는
확률은 아니며, 임계값 0.70은 그 상태에서의 잠정치다. 온도 스케일링 등
별도 교정을 로드맵 스트레치에 남겼다.
