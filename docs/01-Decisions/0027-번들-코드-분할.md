# ADR-0027: 번들 분할 — 라우트가 아니라 차트 하나

## 상태

채택됨. Phase 8의 마지막 항목.

## 배경

프론트 번들이 **683 kB (gzip 201 kB)** 단일 청크였고 대부분이 Recharts다.
그런데 랜딩 페이지는 `/`(검색 어시스턴트)이고, **차트는 `/items/:id`에서만**
쓰인다. 첫 화면이 쓰지도 않는 차트 라이브러리를 받고 있었다.

## 착수 전 전제 확인

"Recharts를 하나만 쓴다"는 전제가 틀리면 분할해도 다시 딸려온다. 그래서 먼저 셌다.

```
recharts를 import 하는 파일   : src/components/PriceChart.tsx  (1곳)
PriceChart를 쓰는 곳          : src/pages/ItemDetail.tsx       (1곳)
차트 라이브러리 의존성        : recharts 뿐
```

간접 유입 경로가 없다. **엔트리 경로에서 lazy 없이 import하는 컴포넌트가 하나만
더 있어도 분할은 무효**가 되므로, 이 확인이 착수 조건이다.

## 결정 1: 라우트가 아니라 컴포넌트 단위로 자른다

| 안 | 대가 |
|---|---|
| **`PriceChart`만 지연** | Suspense 경계 1곳 |
| 라우트 3개 전부 지연 | Suspense 3곳 + 이동마다 깜빡임. `ItemDetail`·`AnomalyQueue` 자체 코드는 작아 **추가 이득이 거의 없다** |

무게가 한 컴포넌트에 몰려 있으므로 거기만 자르는 것이 정확하다.

## 결정 2: 성공 기준을 숫자가 아니라 **구조**로 건다

ADR-0026에서는 예측값을 걸었다. **반증할 인과 모델이 있었기** 때문이다 —
"루프 블로킹이 원인이면 제거 시 격리값에 수렴한다", 빗나가면 모델이 틀린 것.

여기엔 그런 모델이 없다. 모듈을 엔트리 청크에서 빼면 그 바이트가 기계적으로
빠지고 **크기는 빌드 출력에서 직접 읽힌다.** 숫자를 미리 적는 건 예측이 아니라
장식이다.

대신 **엔트리 청크에 Recharts가 없을 것**을 기준으로 걸고, 크기는 실측을
보고한다.

## 결정 3: 지연 로딩이 만드는 UX 변화를 그 자리에서 상쇄한다

지연 로딩은 **없던 로딩 순간을 만든다.** "기능 무변화"가 아니라 "기능은 같고
로딩 순간이 추가됨"이 정확한 표현이다. 두 가지로 다뤘다.

- **마운트 시 미리 받는다.** 청크 다운로드와 시세 조회는 서로 독립인데, 차트가
  그려지는 건 예측이 도착한 뒤다. 그때 청크를 받기 시작하면 두 대기가 **직렬로
  붙는다.** `useEffect`에서 `import()`를 미리 걸어 병렬로 만든다
- **폴백 높이를 차트와 같은 260px로** 맞춘다. 다르면 청크가 도착하는 순간 아래
  내용이 밀려 레이아웃이 튄다

## 결과 (실측)

| | 이전 | 이후 |
|---|---|---|
| 엔트리 청크 | 683.15 kB / gzip **201.29 kB** | 288.36 kB / gzip **92.22 kB** |
| `PriceChart` 청크 | — | 394.74 kB / gzip 108.56 kB (지연) |
| 엔트리의 `recharts` 참조 | 15회 | **0회** |

**첫 로드 gzip 54% 감소** (201.29 → 92.22 kB).

## 확인하지 못한 것

**폴백이 실제로 자연스러운지는 사람이 봐야 한다.** 청크가 분리됐다는 기계적
확인과 "빈 화면이 깜빡이지 않는가"는 다른 문제다. 브라우저 자동화 도구가 없어
직접 확인하지 못했다 — ADR-0013의 "UI를 렌더링해서 눈으로 확인하지 못했다"와
같은 한계이고, 그때처럼 사람이 확인한 뒤 이 문단을 갱신한다.

미리 받는 처리 때문에 **정상 경로에서는 폴백이 보이지 않을 가능성이 높다**
(청크가 시세 조회보다 먼저 끝난다). 느린 회선에서는 보일 수 있고, 그때를 위해
높이를 맞춰뒀다.

## 고려한 대안

| 대안 | 기각 사유 |
|---|---|
| 라우트 3개 전부 지연 | 무게가 한 컴포넌트에 몰려 있다. 경계만 늘고 이득은 거의 없다 |
| `manualChunks`로 vendor 분리 | Recharts가 엔트리에 남는다 — 파일만 나뉘고 **첫 로드에 받는 건 그대로**다 |
| Recharts를 가벼운 차트로 교체 | 번들 문제를 라이브러리 교체로 푸는 건 범위가 다르다. 지연 로딩으로 첫 로드 문제는 해결된다 |
| 크기 감소분을 미리 예측 | 반증할 모델이 없다(위) |

## 영향

- 첫 로드가 절반 이하로 줄었다. 4 OCPU 공유 환경에서 특히 의미가 있다
- `/items/:id` 최초 진입에서 108 kB를 추가로 받는다 — **필요할 때만**
- 지연 로딩 대상이 늘어나면 **엔트리 경로에서 정적 import되지 않는지**를 매번
  확인해야 한다. 하나만 새면 분할이 무효가 된다
