# ADR-0009: 이상거래 탐지는 오토인코더로 하되, 규칙의 대체재가 아니라 보완재로 둔다

## 상태

채택됨

## 배경

계획서상 이상거래 탐지는 "Autoencoder 재구성 오차 → 피처 기여도 분해 →
LLM 설명"이고, Isolation Forest는 명시적으로 제외 대상이다. 오토인코더를
고른 유일한 근거는 **설명가능성**이다 — Isolation Forest는 "이상함"까지만
말하지만, 오토인코더는 재구성 오차를 피처별로 쪼갤 수 있어 "무엇이 이상한지"를
말할 수 있다. GM이 검토 큐에서 판단하려면 후자가 필요하다.

구현에 들어가면서 정할 것이 네 가지였다: 입력 피처, 이상치 정의, 임계값 산정,
그리고 **오토인코더가 규칙보다 실제로 나은지 어떻게 확인할 것인가**.

마지막이 핵심이다. 이 단계에서 가장 위험한 함정은 순환논증이다. "가격이
시세의 5배 이상이면 이상"이라는 규칙으로 이상치를 주입하고 그걸 오토인코더가
잡아냈다고 보고하면 아무것도 증명하지 못한다. 규칙이 만든 걸 규칙으로 되찾은
것뿐이고, 그럴 거면 모델이 아니라 그 규칙을 쓰면 된다.

## 결정

**1. 피처는 원시값이 아니라 맥락 대비 상대값 11개.** 오토인코더는 "체결가
50만원"만 보고 그게 이 아이템 기준 비싼지 알 수 없다. Phase 5-1에서 가격을
비율로 정규화한 것과 같은 원칙이다.

시세 대비 체결가 / 거래 금액 / 수량 / 체결 시각(sin·cos) / 구매자·판매자
계정 나이 / 구매자·판매자 24시간 거래 건수 / 동일 쌍 7일 반복 횟수 / 경매 여부.
행동 피처는 시간순 한 번의 패스로 **과거만 보고** 계산한다.

스케일링은 StandardScaler가 아니라 중앙값/IQR이다. 학습셋에 이상치가 섞일 수
있는데 평균·표준편차는 거기에 끌려간다.

**2. 이상치는 피처가 아니라 행동으로 주입한다.** `seller_trades_24h = 50`을
직접 세팅하지 않고, 같은 판매자의 거래 50건을 24시간 안에 실제로 생성한다.
피처는 그걸 보고 파생된다. 이게 순환논증을 막는 실질적 장치다.

GM 도메인 시나리오 5종: 자전거래 / 계정 도용 투매 / 작업장 대량 유통 /
대포 계정 고액거래 / 복합 미세 이상.

**3. 임계값은 학습에 쓰지 않은 정상 데이터에서 잡는다.** 정상 데이터를
학습 / 임계값 홀드아웃 / 평가용으로 **3분할**한다. 분할은 시간순이다
(24시간·7일 롤링 피처가 있어 무작위 분할은 누수).

임계값 자체는 홀드아웃 재구성 오차의 백분위수다. 이러면 임계값이 "정상
트래픽의 몇 %를 검토 큐에 올릴 것인가"로 직접 읽힌다. 이건 통계값이라기보다
**운영값**이다 — GM 팀이 하루에 소화 가능한 알림 수가 실질 상한이다.

임계값은 **테넌트별 dict**로 저장한다. 게임사마다 거래 분포가 달라 전역 값
하나를 공유하면 어느 한쪽은 반드시 어긋난다. 지금은 원소가 하나지만
멀티테넌시는 이 프로젝트 전체의 아키텍처 원칙이고, 이 컴포넌트만 예외로 둘
이유가 없다.

**4. 규칙 기준선을 두 개 둔다.** Phase 5-1의 나이브 기준선과 같은 역할이다.

- `가격 |z|`: 가격 하나만 본다 — "그냥 시세 대비만 봐도 되는 것 아닌가"
- `전 피처 max |z|`: 다변량이되 **상호작용은 못 본다**

두 번째가 핵심 통제군이다. 오토인코더의 유일한 우위는 상호작용이므로,
max |z|가 그 우위를 정확히 분리해낸다.

**5. 구조는 11 → 8 → 4 → 8 → 11.** 병목이 넓으면 항등함수를 학습해서
이상치까지 잘 재구성해버린다.

## 고려한 대안

1. **Isolation Forest** — 계획서 제외 대상. 설명가능성이 없다. 다만 아래
   결과를 보면 "희귀함"을 재는 계열의 방법이 필요한 것은 사실이고, 그 역할은
   `max |z|` 규칙이 맡는다.
2. **지도학습 분류기** — 실거래 이상 라벨이 없다. 합성 라벨로 지도학습하면
   주입 규칙을 그대로 학습해 순환논증이 된다.
3. **학습셋 재구성 오차로 임계값 산정** — 낙관 편향. 실측으로 확인했다
   (`docs/05-Troubleshooting/오토인코더-임계값-학습셋-편향.md`).
4. **규칙 기반 탐지만** — 아래 결과대로 단일 축 이상에는 규칙이 더 낫지만,
   여러 축에 흩어진 증거는 못 잡는다. 그래서 대체가 아니라 병행이다.

## 결과

정상 3분할: 학습 18,673 / 임계값 홀드아웃 3,874 / 평가 4,155.
평가셋 이상거래 137건(기저율 3.30%).

임계값(p99): 학습셋 기준 7.98, **홀드아웃 기준 8.41(채택)**. 학습셋 임계값을
홀드아웃에 적용하면 정상의 1.32%가 알림 — 의도한 1.00%의 1.32배다.

| 방법 | PR-AUC | 정밀도(R-precision) |
|---|---|---|
| 오토인코더 | 0.679 | 0.591 |
| 규칙: 전 피처 max \|z\| | 0.669 | 0.599 |
| 규칙: 가격 \|z\| | 0.335 | 0.292 |

| 유형 | 오토인코더 | 가격 \|z\| | max \|z\| |
|---|---|---|---|
| 자전거래 | 100% | 100% | 100% |
| 계정 도용 투매 | 100% | 100% | 100% |
| 작업장 대량 유통 | **81%** | 0% | 40% |
| 대포 계정 고액거래 | 12% | 0% | **100%** |
| 복합 미세 이상 | **13%** | 0% | 0% |

### 핵심 결론 — 오토인코더는 규칙보다 낫지 않다. 다른 것을 잰다

전체 PR-AUC는 max |z|와 사실상 동률이다(0.679 vs 0.669). 유형별로 보면
갈리는 지점이 분명하다.

대포 계정에서 오토인코더가 12%로 크게 진 것이 버그인지 확인했더니 메커니즘
이었다. 대포 계정의 `log_buyer_age` 입력은 −3.77(정상 평균 −0.07)인데
**오토인코더가 −3.97로 재구성한다 — 이상값을 105% 따라간다.** 제곱오차는
0.08에 불과하다. 정상 데이터에도 신규 계정 꼬리가 실재하므로 오토인코더가
그 영역을 학습해버린 것이다.

> **재구성 오차는 "희귀함"이 아니라 "재현 불가능함"을 잰다.**
> `max |z|`는 희귀함을 잰다. 둘은 다른 질문이다.

- 오토인코더 우위: 증거가 여러 축에 흩어질 때 (작업장 81% vs 40%,
  복합 미세 13% vs 0%)
- 규칙 우위: 한 축만 극단인데 그 값이 학습 분포에 표현돼 있을 때 (대포 계정)

따라서 **오토인코더로 규칙을 대체하지 않고 병행한다.** 계획서가 오토인코더를
고른 이유(설명가능성)는 그대로 유효하고, 탐지 범위는 규칙이 보완한다.

### 구현

`ai/app/services/anomaly/` 에 features / dataset / scenarios / model /
detector / evaluation / pipeline. 학습은 `python -m scripts.train_anomaly`,
서빙은 `POST /api/anomaly/detect`(단건)와 `GET /api/anomaly/alerts`(검토 큐).

설명 출력 예:

```
#23659  score=2055.41  가격배율=0.05  [계정 도용 투매]
    시세 대비 체결가 91% / 거래 금액 3% / 구매자 계정 나이 3%
```

`hour_sin`/`hour_cos`처럼 한 개념을 두 축으로 인코딩한 피처는 합쳐서
보여준다. LLM 자연어 설명은 Phase 6 Intent Router가 붙을 때 연결한다.

## 알려진 한계

### 1. 알림 큐가 가격 이상치로 도배된다

점수 상위 8건이 전부 계정 도용 투매다(점수 1,200~2,000 vs 작업장 11).
`log_price_ratio`는 IQR이 작아 조금만 벗어나도 z가 크게 잡히기 때문이다.
점수 순 정렬만으로는 작업장·복합 미세가 큐 상단에 오르지 못한다. 유형별
쿼터나 로그 스케일 점수가 필요하다.

### 2. 병목 크기를 원칙적으로 고를 방법이 없다

4차원은 입력 차원의 1/3이라는 휴리스틱으로 정했고 튜닝하지 않았다. 평가셋
PR-AUC로 고르면 테스트셋 쇼핑이고, 홀드아웃 재구성 오차로 고르면 병목이
클수록 항상 유리해서 기준이 되지 못한다. 라벨 없이 병목을 고르는 방법은
열어둔 문제다.

### 3. 측정 범위

- **합성 데이터다.** 이상치는 GM 도메인 지식으로 만든 시나리오이지 실제
  적발 사례가 아니다.
- **기저율 3.30%는 실제(1% 미만)보다 높다.** PR-AUC가 낙관적으로 나오므로
  기저율에 둔감한 유형별 재현율을 주 지표로 본다.
- **학습셋이 깨끗하다는 전제 위에 있다.** 실서비스에서는 보장할 수 없다.
  오토인코더는 오염률이 낮으면(<1%) 견디는 편이지만 이 전제 자체가 한계다.
- **단일 실행이다.** 시드 분산을 재지 않았다.
