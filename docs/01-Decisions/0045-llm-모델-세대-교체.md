# ADR-0045: LLM 모델 세대 교체 — 가장 최신을 못 쓰는 이유는 `temperature` 였다

## 상태

채택됨. `gpt-4o-mini` → **`gpt-5.4-mini-2026-03-17`**,
`claude-sonnet-4-5` → **`claude-sonnet-4-6`**. 테스트 AI **292 → 296**.

## 배경

**모델 이름에는 근거가 없었다.** ADR-0004 는 *프로바이더*를 정한다(OpenAI 주,
Claude 는 두 용도만, Gemini/DeepSeek 배제). 그런데 `gpt-4o-mini` 와
`claude-sonnet-4-5` 가 왜 그 값인지는 **어디에도 적혀 있지 않았다.** 초기에 정한
기본값이 한 번도 재검토되지 않은 것이고, 이 저장소가 반복해서 잡아낸
*"그건 결정이 아니라 그렇게 된 것"* 의 또 한 사례다.

바꾸는 데 실제 비용도 있었다 — **이 저장소의 품질 수치 거의 전부가
`gpt-4o-mini` 기준**이다(ADR-0017 · 0038 · 0039 · 0040 · 0007). 근거 없이 바꾸면
그 숫자들이 **지금 쓰지 않는 모델에 대한 주장**이 된다. 그래서 바꾸되,
**하네스를 다시 돌려 숫자를 새로 만든다.**

## 결정 1: 가장 최신 모델은 쓸 수 없다 — 이유가 측정됐다

먼저 API 에서 **실제 모델 ID** 를 받아왔다. 마케팅 이름("GPT-5.6 Sol")과 API ID 는
다르고, 추측하면 전부 404 다.

그다음 우리 클라이언트로 `temperature=0` 을 보내봤다.

| 모델 | `temperature=0` |
|---|---|
| `gpt-5.6-sol` · `gpt-5.6-terra` · `gpt-5.6-luna` | **거부** |
| `gpt-5.5` · `gpt-5-mini` | **거부** |
| **`gpt-5.4` · `gpt-5.4-mini` · `gpt-5.4-nano`** | 수용 |
| `claude-sonnet-5` · `opus-4-7` · `opus-4-8` | **거부** |
| **`claude-sonnet-4-6`** · `sonnet-4-5` · `haiku-4-5` | 수용 |

```
Unsupported value: 'temperature' does not support 0 with this model.
Only the default (1) value is supported.          # OpenAI
`temperature` is deprecated for this model.        # Anthropic
```

추론 내장 세대가 온도를 1로 고정한다. 그걸 쓰면 **ADR-0017 이 세운 결정성이
통째로 무너진다** — 이 프로젝트가 여섯 페이즈 동안 비결정성의 원인을 못 찾다가
`temperature` 미전달이었음을 발견한 그 결과다.

**그래서 "왜 최신이 아니냐"의 답은 취향이 아니라 제약이다.** 그리고 그 제약은
이제 재현 가능한 한 줄짜리 검사로 남아 있다.

## 결정 2: 날짜를 고정한다

`gpt-4o-mini` 는 **부동 별칭**이었다. ADR-0043 이 RAGAS 변동을 읽을 때 정확히 그
한계에 부딪혔다 — `context_precision` 이 0.0148 움직였는데 **모델이 바뀐 것인지
우리가 바꾼 것인지 구분할 수 없었다.**

`gpt-5.4-mini-2026-03-17` 은 날짜가 박혀 있다. 앞으로 같은 코드가 다른 답을 내면
그건 우리 쪽이다.

폴백은 `claude-sonnet-4-6`(별칭)으로 뒀다. **하네스가 재는 대상이 아니라서**
재현성 이득이 적고, 폴백은 오래 사는 쪽이 낫다 — ADR-0042 가 적었듯 *동작할 수
없는 폴백은 장애가 날 때까지 그 부재가 감춰진다.*

## 결정 3: 하네스를 다시 돌린다 — 대조군을 같은 날 함께

**기록된 값과 비교하지 않는다.** 옛 수치는 예전 측정이고 `gpt-4o-mini` 는 부동
별칭이라 그 사이 드리프트했을 수 있다. 그래서 **같은 날 두 모델을 나란히** 쟀다.

### 재작성 결정성 (ADR-0017)

| | 필터 추출 | 토큰집합(재작성 텍스트) | 불안정 |
|---|---|---|---|
| gpt-4o-mini ①② | 0.990 / 1.000 | **1.000 / 1.000** | 0-in-10 |
| gpt-5.4-mini ①② | 0.990 / 0.990 | **0.950 / 0.920** | 3-in-10 |

**새 모델이 재작성 텍스트에서 덜 결정적이다.** 대조군이 기록값(0.990)보다 오히려
좋게 나왔으므로 **옛 모델의 드리프트가 아니라 새 모델의 성질**이다.

**그런데 필터 축은 동점**이고, 0건 판정·하드필터를 결정하는 것은 필터 축이다.
그래서 하류 영향을 따로 쟀다 — 아래.

### 검색 품질 (ADR-0014/0015) — 결정성 악화의 **실제 대가는 0**

| | 재작성 텍스트 | 적합 / 부적합 |
|---|---|---|
| gpt-4o-mini | `"강화 방어구 갑옷"` | **20 / 14** |
| gpt-5.4-mini | `"강화 갑옷 방어구 로브"` | **20 / 14** |

재작성 문구도 리랭커 점수도 움직였는데 **적합·부적합 판정은 한 건도 안 바뀌었다.**
0건 질의도 같은 1건(`"3만원 이하 불속성 검"`)이다.

> **결정성은 그 자체가 목적이 아니라 결과를 지키는 수단이었다.** 수단이 흔들려도
> 결과가 안 흔들리면 대가가 아니다. 이걸 재지 않고 "결정성이 나빠졌으니 기각"
> 했다면 **측정 가능한 것을 안 재고 기각**하는 셈이었다.

### 원소 추출 (ADR-0040) — 결정적 개선, 그리고 새 결함

| 그룹 | gpt-4o-mini (후처리 후) | gpt-5.4-mini | **+ 부정형 수정** |
|---|---|---|---|
| 무속성 | 39/42 (93%) *(전 69%)* | 42/42 *(전에도 100%)* | 42/42 |
| 타속성 | 21/24 (88%) | 24/24 | 24/24 |
| 미언급 · 저항 | 100% | 100% | 100% |
| **부정형** | **9/9** | **7/9 (오채움 2)** | **9/9** |
| 합계 | 111/117 | 115/117 | **117/117** |
| 사전 등록 기준 | **2 FAIL** | 1 FAIL | **5개 전부 PASS** |

세 가지가 나왔다.

1. **`fill_missing_element` 가 거의 죽은 코드가 됐다** — 후처리가 손댄 판정이
   10~12건에서 **0건**으로. 모델이 이미 맞힌다.
2. **ADR-0040 이 미해결로 남긴 둘이 닫혔다** — 일부러 처리하지 않은 표현
   `"속성 안 붙은 신발"` 과, 6/6 으로 `null` 이던 `"어둠 속성 로브"`.
3. **대신 새 결함이 생겼다.** `"무속성 빼고 보여줘"` 에 모델이 **스스로**
   `무속성` 을 채운다. ADR-0040 이 *"안 하는 것보다 훨씬 나쁘다"* 고 적은
   오류다 — 사용자가 **빼달라고 한 것만** 돌려준다.

**채우기만 하던 함수가 지우기도 하게 했다.** 이미 있는 `_NEGATED` 정규식을
그대로 쓰고, **`무속성` 일 때만** 지운다 — 그래서 ADR-0040 이 성질로 내세운
"지금 잘 되는 다른 속성에 닿을 수 없다" 가 유지된다. 재채점은 **API 호출 0회**로
끝났다(수집/채점 분리가 설계대로 값을 했다).

### 도메인 게이트 (ADR-0039) — 유일하게 애매한 축

| | gpt-4o-mini | gpt-5.4-mini |
|---|---|---|
| 미검출(도메인 밖 통과) | 5/41 · **V1 2/38** | **3/41 · V1 0/38** |
| 오거부 — **일반 질의 141건** | **0** | **0** |
| 오거부 — 경계 질의 32건 | 5 (15.6%) [5.3, 32.8] | 7 (21.9%) [9.3, 40.0] |
| 오거부 전체 509건 | 0.79% (PASS) | **2.55% (FAIL)** |

새 모델은 **더 보수적**이다. 놓치는 건 줄고 거절은 는다.

- **평범한 질의 141건은 양쪽 다 오거부 0.** 회귀가 사용자 대부분에게 안 닿는다.
- **경계 두 값의 95% 구간이 크게 겹친다** — n=32 에서 5 vs 7 은 구분되지 않는다
  (사례집 22 가 적어둔 그대로다).
- 반면 미검출은 **동결된 V1 세트에서 2/38 → 0/38** 로 명확히 좋아졌다.

**어느 오류가 더 나쁜가**로 갈린다. ADR-0039 를 만든 사건은 *놓침*이었다 —
`"삼성전자 주식"` 에 다른 아이템의 진짜 예측값으로 답한 것. 그 무게로 보면 새
모델이 낫다.

> **다만 프롬프트는 gpt-4o-mini 에 맞춰 5회 반복해 다듬은 것**이다(ADR-0039).
> **한 모델에 맞춘 프롬프트는 다른 모델로 그대로 옮겨가지 않는다** — 오거부
> 증가의 상당 부분이 그 탓일 수 있다. 다시 다듬는 것은 별개 라운드이고,
> **held-out 세트를 한 번 더 태우는 대가**가 있다(ADR-0039 는 "한 번만 쓴다" 를
> 규칙으로 적었다).

### 지연

스모크 측정에서 **2403ms → 796~824ms (약 3배)**. LLM 이 검색 지연의 97% 이므로
(ADR-0020) 체감에 직접 온다.

## 고려한 대안

| 대안 | 기각 이유 |
|---|---|
| `gpt-5.6-luna`(최신·최저가) | **`temperature=0` 거부.** 결정성이 무너진다 |
| `gpt-5.5` / `gpt-5.6-terra` / `sol` | 같은 이유 |
| `gpt-5.4-nano` | 스모크에서 필드 스왑(`subcategory`/`element`)이 gpt-4o-mini 와 같게 나왔다. 비용이 제약이 아닌 규모라 mini 를 골랐다 |
| `claude-sonnet-5` / `opus-4-8` | `temperature` 폐기. 폴백이 흔들리면 **이미 망가진 상황에서 답이 더 나빠진다** |
| 별칭(`gpt-5.4-mini`) 사용 | 부동 별칭이 ADR-0043 에서 실제로 진단을 막았다 |
| 안 바꾸고 유지 | 근거가 없다. 게다가 폐기되면 라이브 데모가 조용히 멈춘다 |
| 바꾸되 재측정 없이 | ADR 다섯 개의 숫자가 **지금 쓰지 않는 모델에 대한 주장**이 된다 |

## 영향

- **`ai/.env` 를 같이 바꿔야 한다.** 코드 기본값은 `.env` 에 덮인다 — 실제로 이
  라운드에서 `anthropic_model` 만 바뀌고 `openai_model` 은 안 바뀌었다
  (`ai/.env` 에 `OPENAI_MODEL` 이 있고 `ANTHROPIC_MODEL` 은 없었다).
  **배포 서버의 `ai/.env` 도 같다** — 안 고치면 옛 모델이 계속 돈다.
- `fill_missing_element` 가 **지우기도 한다.** 이름은 그대로 뒀다 — ADR-0040 ·
  DevLog 가 그 이름으로 기록돼 있고, 과거 기록을 바꾸는 대가가 더 크다
  (오늘 `ir-gate` 이름을 CI 화면만 고치고 파일명은 둔 것과 같은 판단).
- 테스트 **292 → 296**. 확장의 안전선(다른 속성은 부정형이어도 불가침)을 포함.
- **하네스 11개의 Windows 크래시를 고쳤다.** `print()` 안의 em dash 가 cp949
  콘솔에서 `UnicodeEncodeError` 를 낸다 — 표는 다 나온 뒤라 결과는 안 잃지만
  **exit 1 이라 자동화가 실패로 읽는다.** 이번 라운드에서 두 스크립트가 그렇게
  죽었다.

## 한계

- **도메인 게이트 오거부 증가는 남는다.** 일반 질의에는 안 닿고 경계는 구분
  불가지만, 전체 기준(≤1%)은 넘었다. 프롬프트를 새 모델에 맞춰 다시 다듬는 것이
  해법이고 그건 별개 라운드다.
- **설명 프롬프트(ADR-0038)와 RAGAS(ADR-0007)는 재측정하지 않았다.** 전자는
  변형 비교라 승자가 바뀌는지가 질문이고, 후자는 2시간짜리다. 둘 다 조건과 함께
  남긴다.
- **재작성 결정성은 실제로 나빠졌다.** 지금 평가셋에서 결과가 안 바뀌었을 뿐,
  코퍼스가 커지면 순위가 흔들릴 여지는 남는다. `evaluate_hard_filters` 가 그걸
  볼 수단이다.
- **한 모델에 맞춘 프롬프트는 옮겨가지 않는다** — 이번 라운드가 그걸 보여줬고,
  다음에 모델을 또 바꿀 때도 같은 재측정이 필요하다.
