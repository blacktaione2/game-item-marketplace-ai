# ADR-0006: 크로스인코더를 영어 전용 ms-marco에서 다국어 mMARCO 모델로 교체한다

## 상태

채택됨 (계획서의 모델 선정을 변경)

## 배경

계획서(`CLAUDE.md`)는 리랭킹 모델로 "ms-marco-MiniLM class model"을
명시했고, 그에 따라 `cross-encoder/ms-marco-MiniLM-L-6-v2`를 ONNX 변환 +
int8 양자화해서 붙였다. 변환 파이프라인 자체는 잘 동작했다.

그런데 실제 한국어 질의로 리랭킹을 돌려보니 **결과가 오히려 나빠졌다.**

질의 `"강화 롱소드"`에 대해:

```
리랭킹 전(RRF): +7 강화 롱소드, +8 강화 롱소드, +9 강화 롱소드, ...
리랭킹 후:      강화 주문서, 미스릴 단검, 만렙 전사 계정, ...
점수:           8.725, 8.628, 8.556, 8.537, 8.524   <- 전부 8.5~8.8에 몰림
```

관련 문서를 위로 올리기는커녕 롱소드 3종을 전부 밀어내고 무관한 문서를
올렸다. 점수도 0.3 폭 안에 뭉쳐 있어 사실상 아무것도 변별하지 못하는
상태였다.

## 원인

모델이 망가진 게 아니라 **토크나이저가 한국어를 못 받는다**는 게 원인이었다.
영어 통제군을 같이 돌려보니 모델 자체는 멀쩡했다:

```
"how to cook pasta" vs "Boiling pasta guide" -> -0.611
                    vs "Car engine repair"   -> -11.193   (제대로 변별)
```

토크나이저를 직접 열어보니 한국어가 자모 단위로 분해되고 있었다:

```
'강화 롱소드'         -> ['ᄀ','##ᅡ','##ᆼ','##ᄒ','##ᅪ','ᄅ','##ᅩ','##ᆼ',...]
'enhanced long sword' -> ['enhanced','long','sword']
```

`ms-marco-MiniLM-L-6-v2`는 영어 MS MARCO로 학습된 영어 WordPiece
토크나이저를 쓴다. 한국어 문자열은 의미 단위가 전부 파괴된 채 들어가므로,
모델은 노이즈를 채점하고 있었다. 점수가 좁은 범위에 뭉쳐 있던 게 바로 그
증상이다.

## 결정

같은 ms-marco/MiniLM 계열의 **다국어 버전**인
`cross-encoder/mmarco-mMiniLMv2-L12-H384-v1`로 교체한다.

mMARCO는 MS MARCO를 다국어로 확장한 데이터셋이므로, 계획서가 의도한
"ms-marco-MiniLM 계열"이라는 성격은 유지하면서 한국어를 실제로 처리할 수
있다. 토크나이저도 정상이다:

```
'강화 롱소드' -> ['▁강화', '▁', '롱', '소', '드']
```

교체 후 같은 질의 결과:

```
리랭킹 후: +9 강화 롱소드, +7 강화 롱소드, +8 강화 롱소드, 강화 주문서, ...
점수:      3.702, 3.267, 3.186, -2.792, -3.719   <- 관련/무관이 6점 이상 벌어짐
```

`"마법사가 쓸 만한 지팡이"` 질의에서도 RRF 4위였던 "얼음 서리 지팡이"를
1위로 올리고, 엉뚱하게 3위에 있던 "게임 머니 1000만 골드"를 상위권 밖으로
밀어냈다 — 리랭커에게 기대하던 바로 그 동작이다.

## 고려한 대안

1. **한국어 전용 크로스인코더** (`Dongjin-kr/ko-reranker`,
   `bongsoo/klue-cross-encoder-v1` 등) — 한국어 성능은 더 좋을 수 있지만,
   계획서가 명시한 "ms-marco-MiniLM 계열"에서 완전히 벗어나고, 다국어
   지원이 필요해질 경우(게임사가 글로벌 서비스면 영문 아이템명이 섞인다)
   다시 갈아타야 한다.
2. **영어 모델 유지 + 질의/문서를 영어로 번역해서 리랭킹** — 번역 LLM
   호출이 검색 경로에 추가로 붙어서 레이턴시/비용 기조에 정면으로 어긋난다.
3. **mMARCO 다국어 모델 (채택)** — 계획서의 모델 계열을 유지하면서
   한국어를 처리한다. 설정(`reranker_model`)으로 빼뒀으므로 나중에 1번
   대안으로 교체하는 것도 한 줄이다.

## 결과

- 모델이 L-6 → L-12로 커지고 어휘 사전도 다국어(XLM-R 계열)라 int8
  양자화 산출물이 **22MB → 112.8MB**로 늘었다. 리랭킹 레이턴시는 후보
  20건 기준 **약 121ms**(웜) 로 측정됐다 — 레이턴시 예산 안이라 판단해
  크기 증가를 수용했다.
- `CLAUDE.md`의 "ms-marco-MiniLM class model" 서술은 이 ADR을 참조하도록
  갱신했다.
- **배운 것**: 모델을 "계획서에 적혀 있으니까" 그대로 붙이면 안 된다.
  파이프라인(ONNX 변환, 양자화, 배치 추론)이 전부 정상 동작해도 모델과
  데이터 언어가 안 맞으면 결과는 조용히 나빠진다. 영어 통제군을 같이
  돌려서 "모델이 고장난 것"과 "모델이 이 언어를 못 하는 것"을 분리한 게
  원인 파악의 핵심이었다 — 앞으로 사전학습 모델을 도입할 때 표준
  절차로 삼을 것.
- 참고: 임베딩 모델은 처음부터 다국어
  (`paraphrase-multilingual-MiniLM-L12-v2`)를 골라서 같은 문제가 없었다.
  Phase 4에서 이 임베딩을 도메인 데이터로 파인튜닝할 예정이다.
