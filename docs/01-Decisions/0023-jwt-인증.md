# ADR-0023: JWT 인증 — 게이트웨이 없이, 테넌트를 클레임으로

## 상태

채택됨. rate limiting은 **다음 라운드(5b)**로 분리했다.

## 배경

Phase 7에서 "인증 없음, 외부 노출 금지"로 미뤄둔 항목이다. 신원은 헤더 두 개
(`X-Tenant-Id`, `X-User-Id`)가 전부였고 서버는 그 값을 **그대로 신뢰**했다.
Spring Security 의존성 자체가 없었다.

**가장 큰 구멍은 인증이 아니라 테넌트였다.** 멀티테넌시가 이 프로젝트의
간판인데 `X-Tenant-Id: 1`은 그냥 문자열이라 누구나 아무 테넌트나 주장할 수
있었다. 인증을 붙이는 값어치의 대부분이 여기 있다.

## 착수 전 실측

| 항목 | 상태 |
|---|---|
| 헤더 사용처 | `ItemController` 6곳 + `TradeController` 2 엔드포인트 |
| AI 서버 | **헤더를 전혀 안 받음.** `tenant_code`가 요청 **본문**에 |
| AI 테스트 93건 | **HTTP 계층을 안 건드림**(`TestClient` 임포트 0) → 손댈 필요 없음 |
| 백엔드 테스트 | `contextLoads()` 1건 |

## 결정 1: API Gateway를 두지 않는다

각 서버가 개별 검증한다.

- **4 OCPU 공유** — 상시 프로세스를 하나 더 띄우는 비용이 이득보다 크다
- 게이트웨이의 주된 이점(단일 오리진)은 **Vite dev proxy가 이미 제공**한다
- **AI 서버는 어차피 자기가 검증해야 한다.** 8000이 직접 열려 있고 비용(LLM)이
  나가는 쪽이 여기다. 게이트웨이를 세워도 그 앞을 우회하는 경로가 남으면 의미가
  없다

대가는 **검증기가 두 벌**이라는 것이다. 완화: 클레임 이름을
`backend/.../security/Claims.java`와 `ai/app/core/auth.py` 상단에 각각 모으고
서로를 가리키게 했으며, **발급은 백엔드만** 한다(파이썬은 검증 전용).
`ai/tests/test_auth.py`가 거부해야 할 것들을 고정한다.

## 결정 2: 데모 토큰 — 발급은 데모, 검증은 진짜

`POST /api/auth/demo-token {userId}` → JWT. **비밀번호를 확인하지 않는다.**
회원가입·비밀번호 관리는 포트폴리오 목적에 보태는 게 없고, HTTPS 없는 공개
데모에 "진짜 인증"이라는 인상만 만든다.

대신 **검증 쪽은 전부 실제로 동작한다** — 서명(HS256), 만료, 발급자, 필수
클레임, 401/403.

경로 이름이 곧 경고다. `/login`이 아니라 `/demo-token`이고, 컨트롤러
javadoc·API 명세·README에 "userId만 알면 누구나 받는다"고 적었다.

클레임 값은 **요청이 아니라 DB에서** 읽는다. 요청이 주장하는 테넌트·역할을 그대로
실으면 헤더를 믿던 예전과 달라지는 게 없다.

## 결정 3: 테넌트를 클레임으로, 헤더는 제거

| 클레임 | 값 | 쓰임 |
|---|---|---|
| `sub` | userId | 행위자 |
| `tenant_id` | 1 | 백엔드 |
| `tenant_code` | `"nexon"` | AI 서버 (ES 인덱스 선택) |
| `role` | `USER`/`ADMIN` | 인가 |
| `exp`/`iss` | 1시간 / `gimp-backend` | |

`tenant_id`와 `tenant_code`를 **둘 다** 싣는다. 예전엔 프론트의 `demo.ts`가 두
표기의 차이를 흡수했는데, 이제 발급 시점에 한 번 해소하고 **출처를 토큰 하나로**
만든다.

AI 서버의 요청 본문·쿼리에서도 `tenant_code`를 **뺐다**(assistant, forecast,
anomaly detect/alerts, search). 토큰과 본문에 같은 사실이 둘이면 어긋날 수 있고
어긋난 걸 검출할 방법이 없다 — **ADR-0022에서 `trade_id` + `id_space`를
`trade_ref` 한 값으로 합친 것과 같은 논리**다.

부수 효과가 하나 있다: 시맨틱 캐시 키가 테넌트별로 갈리는데, `tenant_code`를
본문으로 받던 동안에는 **남의 테넌트 캐시를 조회하도록 요청할 수 있었다.**

## 결정 4: 역할 인가는 GM 검토 큐 한 곳

`GET /api/anomaly/alerts`에만 `require_admin()`을 건다. 이 큐는 다른 사용자의
거래 내역과 상대방 id를 그대로 보여주므로 일반 사용자가 볼 것이 아니다.

**백엔드에는 역할 검사 대상이 없다.** 없는 대상을 만들지 않았다.

## permitAll — 각각 이유가 있다

| 경로 | 이유 |
|---|---|
| `/actuator/prometheus` | **부하 하네스가 스크레이프한다.** 잠그면 에러가 아니라 **빈 차분**이 나와서 조용히 잘못된 측정이 된다 |
| `/actuator/health`, `/api/health` | 헬스체크 |
| `/api/auth/demo-token` | 토큰을 받으러 오는 길. 잠그면 순환이다 |
| AI `/health`, `/metrics` | 같은 이유. 사설망 전제 |

`AuthenticationTest.부하_하네스가_읽는_메트릭은_잠기지_않는다()`가 이걸 고정한다.

## 검증 (실측)

| 확인 | 결과 |
|---|---|
| 토큰 없이 구매 | **401** |
| 쓰레기 토큰 | **401** |
| 정상 토큰으로 조회 | **200** |
| 정상 토큰 + `X-Tenant-Id: 2` 덧붙임 | **200** (헤더가 실제로 죽었다) |
| `alerts` — 토큰 없음 / USER / ADMIN | **401 / 403 / 200** |
| `actuator/prometheus` 인증 없이 | **200** |
| 부하 하네스 오버셀 단언 | **0건 유지** (1946 == 1946) |

테스트: AI **93 → 108건**, 백엔드 **1 → 10건**.

**백엔드에 행동을 단언하는 테스트가 처음 생겼다.** ADR-0021에 "초록 뱃지를
백엔드가 검증됐다는 뜻으로 읽으면 안 된다"고 적어야 했던 상태가 일부 해소됐다.
시드 데이터에 의존하지 않도록 필요한 행을 테스트가 직접 만든다 — CI는 빈 DB로
뜬다.

## 처리량 — 인증 탓이 아니다 (측정으로 기각)

같은 명령(`purchase contended 20 30s`)이 ADR-0020의 105.9/s가 아니라 **64/s**를
냈다. 인증이 의심됐지만 **아니다.**

- **Security 필터체인은 요청당 0.7ms**로 실측됐다(전체 312ms의 **0.22%**).
  actuator가 `spring_security_filterchains_seconds`를 공짜로 준다
- 인증은 락 **바깥**에서 끝나는데 락 **보유**(DB 트랜잭션)가 0.0068 → 0.0114s로
  올랐다. 인증 경로 밖의 변화라는 뜻이다
- `trades` 테이블 누적(47,052행)도 의심했으나 **시드를 다시 적용하고 재측정해도
  64/s** — 기각
- 대기·보유가 **같은 배수(1.67×)**로 늘었고 대기/보유 비(26×)와
  실측/이론상한 비(0.72)가 **그대로**다 → 시스템 동작이 아니라 박스 전체가
  느려진 쪽

**귀속시킬 근거가 없으므로 귀속시키지 않는다.** 대신 `load/README.md`에 "절대
처리량을 세션 간에 비교하지 말 것, 기준선은 같은 세션에서 다시 뜰 것"을 규칙으로
남겼다. 이건 ADR-0020이 "부하 생성기 동거"라고만 적었던 한계의 구체화다.

## 고려한 대안

| 대안 | 기각 사유 |
|---|---|
| **API Gateway 신설** | 4 OCPU에 상시 프로세스 추가. 단일 오리진은 dev proxy가 이미 제공하고, AI 서버는 어차피 자체 검증이 필요하다 |
| **실제 비밀번호 로그인** | 회원가입·해시 관리가 붙는데 얻는 건 "bcrypt를 썼다" 하나다. HTTPS 없는 공개 데모에 잘못된 인상을 준다 |
| **헤더 유지 + JWT를 신원 전용으로** | 같은 사실의 출처가 둘이 된다. 토큰과 헤더가 어긋나게 올 수 있고 검출할 방법이 없다 |
| **jjwt 라이브러리** | `oauth2-resource-server`가 Nimbus 인코더/디코더를 함께 주므로 발급·검증을 한 계열로 끝낼 수 있다 |
| **`/alerts`를 프론트 라우팅으로만 숨기기** | 이미 그렇게 돼 있었고, 그건 접근 제어가 아니다. URL을 직접 치면 열렸다 |

## 영향

- 백엔드 `@RequestHeader` **8곳 제거**. 서비스 계층 시그니처는 무변경 —
  바뀐 건 tenantId가 **어디서 오는가**뿐이다
- AI 서버 5개 엔드포인트에서 `tenant_code` 제거 (**요청 형식 변경**)
- 프론트: `App.tsx`가 사용자 전환 시 토큰을 받고, `api.ts`가 `Authorization`을
  붙인다. `demo.ts`의 값들은 이제 **서버로 나가지 않는다**(화면 표기용)
- k6 두 스크립트가 `setup()`에서 토큰을 받는다. **`ai-search.js`가 백엔드에
  의존하게 됐다** — 발급자가 백엔드뿐이다
- **`JWT_SECRET`은 두 곳에 같은 값**이 필요하다(저장소 루트 `.env`, `ai/.env`).
  `OPENAI_API_KEY`가 한 곳인 것과 다르다. 다르면 발급은 되는데 AI 서버만 401을
  내므로 증상이 헷갈린다
- Boot 4에서 `@AutoConfigureMockMvc`가
  `org.springframework.boot.webmvc.test.autoconfigure`로 옮겨졌다 —
  `spring-boot-4-autoconfigure-공통패턴` 사례가 하나 늘었다

## 남은 것

**여전히 이 배포를 외부에 노출하면 안 된다.** 발급이 무인증이고 HTTPS가 없다.
README의 경고 블록은 "인증이 없다"에서 "발급이 데모다"로 내용을 바꿔 유지한다.
