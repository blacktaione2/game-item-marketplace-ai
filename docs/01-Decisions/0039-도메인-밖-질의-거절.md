# ADR-0039: 도메인 밖 질의를 거절한다

## 상태

채택 (2026-08-07). 사용자가 배포된 화면에서 잡았다.

## 배경

`"삼성전자 주식 어때?"` 를 입력하자 이렇게 답했다.

> 삼성전자 주식의 최근 거래가는 약 **26,090원**이며, 앞으로 일주일 동안의
> 가격은 소폭 상승할 것으로 보입니다. 예상되는 가격은 26,250원에서
> 26,390원 사이로, 전체적으로 약 0.99%의 상승이 예상됩니다.

**숫자는 전부 진짜다.** `게임 머니 1000만 골드` 의 실제 예측값이고, 화면에는 그
아이템 카드까지 같이 떠 있었다. **거짓인 것은 주어 하나뿐이다.**

### 경로

| 단계 | 무슨 일 |
|---|---|
| 룰 | **기권** — `"어때"` 는 어느 패턴에도 없다 |
| 분류기 | `price_forecast` 0.9179. **출력 공간에 "내 도메인이 아니다" 가 없다** |
| `_has_target` | `"삼성전자"` 가 불용어가 아니라 통과 → 시세 분기 확정 |
| `run_search(size=1)` | **kNN 은 어떤 질의에도 k 건을 돌려준다** → 게임 머니 |
| `forecast_price` | 그 아이템의 **진짜** 예측 |
| 설명 LLM | `query` 와 `result` 를 둘 다 받고 **질의의 주어를 골랐다** |

### 결함은 둘이다

1. **라우터에 거절이라는 출력이 없다.** 어떤 질의든 5개 의도 중 하나로 배정된다.
2. **시세 설명이 질의를 되풀이한다.** `result["name"]` 을 손에 쥐고도 사용자의
   주어를 택했다. ADR-0036 이 검색 분기에 세운 규칙 — *결정 단계가 이미 확정한
   것을 LLM 이 다시 말하게 하면 지어낸다* — 이 시세 분기에 적용되지 않은 채
   남아 있던 **드리프트**다.

## 어느 분기를 막아야 하는가 — 먼저 무료로 쟀다

도메인 밖 질의 38건을 손으로 쓰고(`app/corpus/out_of_domain.py`) 라우터에
그대로 태웠다. LLM 호출이 없으므로 공짜다.

| 분기 | 38건 중 | 필요한 장치 |
|---|---|---|
| `item_search` + `price_forecast` | **22 (58%)** | 게이트 → 확정 거절 |
| `compound` (에이전트) | **7 (18%)** | MCP 도구가 **문장으로 된 안내**를 돌려준다 |
| `faq_smalltalk` | **9 (24%)** | **이미 안전 — 손대지 않는다** |

세 번째가 이 라운드에서 하나 안 만든 것이다. `_DEFAULT_FAQ` 가 이미
*"아이템 검색, 시세 확인, 이상거래 점검을 도와드릴 수 있습니다"* 라고 답한다 —
LLM 0회, 결정적, 범위를 밝히며 거절하는 문장이다. **아무것도 안 해도 맞는 경로에
게이트를 더하면 그건 장식이고, 장식은 거짓 안심을 판다.**

> 같은 질의가 실행마다 다른 분기로 간다. 로컬 분류기는 `"삼성전자 주식 어때?"`
> 를 `compound`(0.5861)로, 배포된 분류기는 `price_forecast`(0.9179)로 보냈다 —
> 학습할 때마다 가중치가 다르기 때문이다. **한쪽만 막으면 안 되는 이유가
> 여기서 하나 더 나온다.**

## 측정 설계 — 양방향을 같이 잰다

거절 게이트의 실패는 양방향이고 대가가 다르다.

| 방향 | 대가 | 안 재면 |
|---|---|---|
| **미검출** (밖을 통과) | 위와 같은 확신에 찬 거짓말 | 고치려던 결함이 남는다 |
| **오거부** (안을 거절) | 멀쩡한 검색이 막힌다 | **"전부 거절" 이 미검출 0% 로 만점** |

- 도메인 밖 **38건** — 손으로 씀. 현실금융·현실상품·게임비거래·생활·일반지식·
  시사·의료법률·업무
- 도메인 안 **509건** — `data/` 의 라벨 검색 질의 141 + 인텐트 발화 중
  `item_search`/`price_forecast`/`compound` 368. `faq_smalltalk`·`anomaly_check`
  발화는 뺐다 — 그 분기는 검색을 타지 않으므로 거절돼도 화면에 영향이 없고,
  넣으면 분모만 키워 지표를 좋아 보이게 만든다
- 경계 **16건** — 도메인 안인데 표면이 밖처럼 보이는 것(`"골드 시세 어때?"`,
  `"만렙 계정 얼마에 팔려?"`). 쉬운 표본만 쓰면 오거부 0은 실력이 아니라 표본 탓이다

### 사전 등록 기준

| 지표 | 기준 |
|---|---|
| 미검출 | <= 10% |
| 오거부 (509건 전체) | <= 1% |
| 오거부 (라벨 141건) | **0건** |
| 필터 회귀 | 신·구 일치율이 **같은 프롬프트끼리의 대조군보다 낮지 않을 것** |

마지막 줄이 요점이다. `temperature=0` 이어도 10건에 1건은 흔들리므로(ADR-0017),
**대조군 없이 "신구 일치율 0.89" 를 보면 프롬프트 탓인지 계측기 바닥인지 알 수
없다.** 그래서 구프롬프트를 두 번 태웠다.

## 결정 1 — 판정을 **별도 호출로 분리**하고 병렬로 던진다

처음 만든 것은 그게 아니었다. `understand_query` 의 JSON 스키마에 `in_domain`
필드를 하나 더하는 안이었고, **LLM 호출이 늘지 않는다**는 게 장점이었다.

### 두 번 재고 두 번 다 기각됐다

| | 1회차 | 2회차 (문구 수정) | 기준 |
|---|---|---|---|
| 미검출 | **0/38** | **0/38** | <= 10% |
| 오거부(509) | 29.9% | **13.4%** | <= 1% |
| 오거부(라벨) | 3/141 | 2/141 | 0건 |
| 필터 일치 (대조군 대비) | -0.106 | -0.071 | 0 이상 |
| **재작성 토큰집합 일치 (대조군 대비)** | **-0.234** | **-0.248** | 0 이상 |

1회차 오거부의 35%가 **시세 질문**이었다(`"골드는 언제쯤 올라?"`,
`"갑옷 사도 후회 안 할까?"`). 규칙에 *"그 거래에 관한 질의면 true"* 라고 썼더니
모델이 **가격 전망을 "거래" 로 읽지 않았다.** 문구를 고쳐 13.4% 까지 내렸다.

**그런데 재작성 손실이 문구를 고쳐도 그대로였다** — -0.234 → -0.248. 즉 문구가
아니라 **스키마에 필드가 하나 늘어난 것 자체**의 대가다. 재작성 텍스트는 BM25 와
kNN 양쪽에 들어가므로 검색 품질에 직결된다.

> **한 호출에 두 일을 시켰더니 둘째가 첫째를 망가뜨렸다.** 비용을 아끼려던
> 설계가 품질을 지불하고 있었고, 그 사실은 **대조군을 뒀기 때문에만** 알 수 있다.

### 그래서 떼어냈다

`app/services/search/domain_gate.py` 에 판정 전용 프롬프트를 두고,
`asyncio.gather` 로 질의이해와 **동시에** 던진다.

```python
understanding, in_domain = await asyncio.gather(
    _timed(understand_query(llm_client, query), "query_understanding_ms"),
    _timed(judge_in_domain(llm_client, query), "domain_gate_ms"),
)
```

얻은 것과 잃은 것이 분명하다.

| | |
|---|---|
| **회귀가 구조적으로 0** | 추출 프롬프트를 아예 건드리지 않는다. 측정 통과가 아니라 **불가능**이다 |
| 문구를 정밀하게 쓸 수 있다 | 판정 전용이라 "검색 질의 분석기" 라는 자기 정체에 눌리지 않는다 |
| **호출 1회 증가** | 검색 분기 `llm_calls` 1 → **2**, 시세 3 |
| 지연은 거의 그대로 | 둘 다 순수 I/O 대기라 느린 쪽 하나치다 |

**판정을 먼저 하고 통과할 때만 이해시키면 도메인 밖 요청의 호출 하나를 아낀다.**
그렇게 하지 않았다 — 아끼는 쪽은 드물고(정상 트래픽은 거의 다 도메인 안이다)
대가는 **모든 요청의 왕복 하나**다.

> `timings` 의 `query_understanding_ms` 와 `domain_gate_ms` 를 **더하면 안 된다.**
> 병렬이라 합이 실제 지연보다 크다. 검색 전체는 `execution_ms` 로 본다.

### 지연 비용은 실측 0이다

로컬에서 파이프라인을 직접 호출해 다섯 케이스를 재봤다.

| 질의 | 질의이해 | 도메인판정 | 실행 합계 |
|---|---|---|---|
| `"금값 시세 알려줘"` | 2769.5ms | **899.7ms** | 2769.6ms |
| `"나이키 운동화 270 있어?"` | 1237.6ms | **746.3ms** | 1237.7ms |
| `"5만원 이하 검 찾아줘"` | 1656.7ms | **865.4ms** | 5377.9ms |
| `"불꽃의 대검 시세 알려줘"` | 1910.4ms | **636.4ms** | 3676.2ms |

**판정이 언제나 더 빠르다** (프롬프트가 1/6 크기다). 그래서 병렬 뒤에 완전히
가려지고, 거절 경로의 `execution_ms` 는 질의이해 시간과 정확히 같다 — 뒤 단계를
건너뛰었다는 런타임 증거이기도 하다.

## 결정 2 — 프롬프트 문구는 다섯 번 고쳤고, 두 번은 내가 나쁘게 만들었다

| 회차 | 방식 | 미검출 | 오거부(509) | 걸린 것의 정체 |
|---|---|---|---|---|
| 1 | 같은 호출 | 0/38 | 29.9% | **시세 질문** — "거래" 를 좁게 읽음 |
| 2 | 같은 호출, 문구 수정 | 0/38 | 13.4% | **대상이 흐릿한 질의** (`"이거 괜찮아?"`) |
| 3 | **별도 호출** | 0/38 | 4.13% | **게임 은어·오타** (`"폭창"`, `"55방각반"`, `"8강 롱검"`) |
| 4 | + 취급 품목 목록, "플레이 방법은 NO" | 0/38 | **5.30%** | **역효과** — 아래 |
| **5 (채택)** | 4의 두 가지를 걷어냄 | **1/38** | **0.59%** | 혼잣말 3건 |
| 6 (확인) | 5와 동일 | 1/38 | **0.98%** | 혼잣말 5건 |

### 4회차 — 목록을 주면 목록 밖을 자른다

포함을 넓히려고 취급 품목을 열거했는데 **배제의 근거로 쓰였다.**

| 넣은 것 | 새로 잘린 것 |
|---|---|
| 취급 품목 목록 | `"고대 유물 조각 구합니다"`, `"수정으로 만든 마법 아이템 찾기"` — 목록에 없는 이름 |
| "플레이 방법은 NO" | `"스킬 쿨타임 줄이는 장신구"`, `"장비 강화 할 때 쓰는 아이템"` — `스킬`·`강화` 라는 **낱말** |

두 번째는 이 저장소가 정규식에서 두 번 겪은 실패가 **프롬프트에서 반복된 것**이다
(`이상 거래` 가 `이상 거래로 판별되지 않았습니다` 를 잡았던 건). 금지 규칙은
의미가 아니라 낱말에 걸린다.

**다섯 실행 내내 미검출이 0/38 이었다는 사실**이 방향을 알려줬다 — 가장 관대한
문구에서도 하나도 안 놓쳤으므로 관대한 쪽으로 밀어도 안전하다는 근거가 있었다.

### 채택된 수치

| | 5회차 | 6회차(확인) | 기준 |
|---|---|---|---|
| 미검출 | 1/38 = **2.6%** | 1/38 = **2.6%** | <= 10% |
| 오거부(509) | 3/509 = **0.59%** | 5/509 = **0.98%** | <= 1% |
| 오거부(라벨 141) | **0건** | **0건** | 0건 |

**두 번 다 통과했지만 6회차는 기준선에 붙어 있다** — 한 건 더 걸리면 미달이다.
여유가 없다는 것을 여기 남긴다. 두 번 돌렸기 때문에 알게 된 사실이고,
한 번만 돌렸다면 0.59% 를 보고 "충분하다" 고 적었을 것이다.

미검출 1건은 두 실행이 동일하다 — `"초보자 직업 뭐가 나아"`. 실패 방향이
온건하다: 검색이 돌아 아이템 몇 건이 나올 뿐, 없는 사실을 지어내지 않는다.

> **이 오거부 수치는 in-sample 이고 낙관적이다.** 규칙을 걸린 표본을 읽고 썼기
> 때문이다. 프롬프트의 예시만은 평가셋 563문장에 **없는 것으로 지어냈다**
> (`"9강 대검"`, `"70방투구"`, `"빙결 스태프"`) — 걸린 문장을 그대로 넣으면
> 오거부율이 실력이 아니라 암기가 된다. 반면 **미검출 쪽은 다섯 번 내내 문구를
> 그쪽에 맞춘 적이 없어** 상대적으로 정직하다.

## 결정 3 — 분기마다 장치가 다르다

### 검색·시세: 확정 거절, 검색 자체를 하지 않는다

`search()` 가 판정만 실어 보내고(`in_domain: false`, `results: []`), 무엇을 할지는
`assistant/pipeline.py` 가 정한다 — `no_results` 와 같은 역할 분담이다.
임베딩·ES·리랭킹은 **아예 건너뛴다.** 태워봐야 kNN 이 k 건을 돌려주고, 그
무의미한 결과가 상류에서 "찾았다" 로 읽히는 게 이 결함의 경로였다.

**시세 분기는 에이전트로 올리지 않는다.** 다른 실패는 "도구를 더 쓰면 풀린다"
라서 올릴 값어치가 있지만, 도메인 밖은 도구를 더 써도 밖이다. 올리면 LLM 을
3~5회 더 태워서 **다른 문장으로 같은 거짓말**을 만든다.

### 응답은 질의를 되풀이하지 않는다

```python
def _out_of_domain() -> dict[str, Any]:   # 인자가 없다
```

*"삼성전자 주식은 다루지 않습니다"* 처럼 대상을 받아 적으면, 게이트가 틀렸을 때
그 문장이 **오히려 설득력을 갖는다.** 무엇을 다루는지만 말하고 무엇을 물었는지는
말하지 않는다. 프롬프트 한 줄이 아니라 **시그니처**가 이걸 보장한다.

### 에이전트: 빈 목록이 아니라 문장을 준다

MCP `search_items` 가 도메인 밖일 때 이렇게 돌려준다.

```python
return [{"note": "이 질의는 게임 아이템 거래소가 다루는 범위 밖입니다. …"}]
```

빈 목록은 **"다루지 않는다" 와 "다루지만 매물이 없다" 를 구분해주지 못한다.**
모델은 후자로 읽고 아는 대로 답한다 — 그게 막으려는 바로 그 행동이다. 예외를
던지지도 않는다. 도구는 실패하지 않았고, 실패로 위장하면 에이전트가 "도구 오류"
를 사용자에게 밝힌다. `estimate_note`(ADR-0038)와 같은 처방이다 — **원시 신호는
읽을 수 있는 말이 아니므로 값 자체를 문장으로 준다.**

## 결정 4 — 설명 프롬프트에 **질의를 넘기지 않는다** (결함 2)

게이트도 LLM 판정이라 100% 가 아니다. 뚫렸을 때 설명이 2차 방어선이 되는지를
따로 쟀다 — `scripts/evaluate_explanation_prompts.py` 에 안 D(질의없음)와
**도메인 밖 질의 × 진짜 예측 결과** 케이스를 넣었다. 관측된 결함을 그대로
재현한 케이스다.

같은 42건(에이전트 경로 제외)으로 채점한 결과다.

| 안 | 누출 | 미완결 | 면책누락 | 모순 | 권유 | **주어채택** | **대상명누락** |
|---|---:|---:|---:|---:|---:|---:|---:|
| A (옛 판) | 20 | 18 | 0 | 0 | 0 | 3/9 | 3 |
| B (**현재 운영**) | 0 | 0 | 0 | 0 | 0 | **1/9** | **9** |
| C (미언급) | 0 | 0 | 0 | 0 | **2** | 0/9 | 0 |
| **D (질의없음)** | **0** | **0** | **0** | **0** | **0** | **0/9** | **0** |

> A·B 는 에이전트 경로 15건을 더 갖고 있어 원래 표의 n 이 57 이었다. **n 이 다른
> 표를 그대로 비교하면 "대상명누락 9 vs 0" 이 프롬프트 차이인지 케이스 구성
> 차이인지 알 수 없다.** 답변을 저장해뒀으므로 같은 집합으로 다시 세는 데 API
> 호출이 들지 않았다(`--score-only` 와 같은 이유).

**B 의 대상명누락 9건은 전부 도메인 밖 케이스다.** 정상 질의 24건에서는 0이다.
즉 현재 운영 프롬프트는 게이트가 작동할 때는 멀쩡하고, 뚫렸을 때 이렇게 답한다.

> 현재 **이 아이템**의 최근 거래가는 29,260원이며 …

주어를 바꾸진 않았지만 **어느 아이템인지도 끝내 말하지 않는다.** D 는 둘 다 0이다.

```
- **결과에 있는 아이템 이름을 답변에 그대로 밝히세요.**
결과: {result}          ← 질의 자리표시자가 없다
```

"질의의 대상을 그대로 쓰지 마세요" 라는 지시로 막지 않았다 — 이 저장소는
**혼동 대상을 이름으로 부르면 오히려 그쪽으로 쏠린 전례**가 있다(97.5% → 22%).
자리표시자가 없으면 되풀이가 **구조적으로 불가능**하다. ADR-0036 이 검색 설명
LLM 을 아예 없앤 것과 같은 처방이고, `_out_of_domain()` 이 인자를 받지 않는 것과도
같다.

이상거래 프롬프트도 같이 바꿨다. 그 분기는 거래 id 가 있어야 돌아 노출이 훨씬
작지만, **같은 결함 계열을 한쪽만 고치면 그게 곧 다음 드리프트**다.

## 결정 5 — 캐시에 저장하지 않는다. **이유는 하나만 겹친다**

| 사유 | 0건 (ADR-0016) | 도메인 밖 |
|---|---|---|
| 판정 근거가 비결정적 (LLM) | O | **O** |
| 답이 낡는다 | O | **X — `"삼성전자 주식"` 은 내일도 밖이다** |

즉 이 응답은 낡지 않는데도 저장하지 않는다. 근거는 오직 첫째다 — 오거부가 굳으면
멀쩡한 검색이 TTL 내내 막힌다. 판정이 결정적으로 바뀌면 이 금지는 다시 볼 수 있다.
**두 금지를 한 덩어리로 읽으면 안 된다.**

## 실패는 통과다

판정이 안 되면(호출 실패, 예상 밖 출력) `True` 를 돌려준다. 게이트가 죽었을 때
서비스가 "아무것도 답하지 않는" 상태가 되는 쪽이 훨씬 나쁘다 —
`understand_query` 가 파싱 실패에 원본 질의로 폴백하는 것, AI 요청 한도가 Redis
장애에 fail-open 하는 것과 같은 방향이다.

대가는 **게이트가 조용히 열린다**는 것이다. 그래서 열린 걸 볼 수 있어야 한다:
로그 경고와 `ai_requests_total{outcome="out_of_domain"}` 이 그 창이다. 오거부율은
배포 전에 평가셋으로 한 번 쟀을 뿐이고 실제 질의 분포는 그것과 다르다 — 이 값이
갑자기 늘면 게이트가 멀쩡한 질의를 막고 있다는 뜻이다.

`_parse` 는 `NO` **로 시작할 때만** 거절한다. `"NO" in text` 로 쓰면
`"YES, 이 문장은 NO 라고 볼 수 없습니다"` 에서 뒤집힌다.

## 고려한 대안

| 대안 | 왜 안 했나 |
|---|---|
| **라우터에 6번째 클래스** | KoELECTRA 재학습. 도메인 밖은 무한집합이라 학습 데이터가 추측이고, 이 분류기는 **신뢰도가 보정 안 됐다고 이미 기록**돼 있다 |
| **BM25 0건 게이트** | 결정적이고 공짜지만, BM25 는 **재작성된** 질의로 돈다. 재작성 프롬프트의 임무가 *"키워드가 걸리도록 동의어를 펼쳐라"* 라 도메인 안 어휘로 세탁될 수 있다 |
| **같은 호출에 필드 추가** | 위 표대로 두 번 측정하고 기각 |
| **게이트 없이 결함 2만 수정** | `"삼성전자 주식 어때?"` 에 `"게임 머니 1000만 골드의 최근 체결가는…"` 이라 답한다. 거짓말은 아니지만 데모에서는 고장으로 읽힌다 |

## 실제로 돌려서 확인했다 — 그리고 하나가 안 밟혔다

단위 테스트는 배선만 고정하고 평가 스크립트는 프롬프트만 잰다. 둘 다 초록이어도
분기가 실제로 그렇게 도는지는 안 본 것이라, 진짜 ES + 진짜 LLM 으로 불러봤다.

| 질의 | 분기 | 결과 |
|---|---|---|
| `"금값 시세 알려줘"` | rules → `price_forecast` | `out_of_domain=true`, 0건, `llm_calls=2` |
| `"나이키 운동화 270 있어?"` | rules → `item_search` | `out_of_domain=true`, 0건 |
| `"삼성전자 주식 어때?"` | `low_confidence` → **에이전트** | 거절은 맞는데 **`llm_calls=1`** |
| `"5만원 이하 검 찾아줘"` | rules → `item_search` | 4건, `llm_calls=2` |
| `"불꽃의 대검 시세 알려줘"` | rules → `price_forecast` | `llm_calls=3`, 답변이 **'불꽃의 대검'을 이름으로 밝힌다** |

세 번째가 요점이다. `llm_calls=1` 은 **도구를 한 번도 안 불렀다**는 뜻이다 —
에이전트가 자기 시스템 프롬프트만으로 거절했고, 내가 넣은 MCP 안내문은 **발동하지
않았다.** 답이 맞았다고 그 경로가 동작한다고 말할 수는 없다.

그래서 도구를 직접 불러 따로 확인했다.

```
[도메인 밖] "삼성전자 주식 시세"  →  {"note": "이 질의는 게임 아이템 거래소가 …"}
[대조군]    "5만원 이하 검"       →  {"item_id": 5, "name": "미스릴 단검", …}
```

> **밟히지 않은 경로는 "동작한다" 고 말할 수 없다.** 이 저장소가 검사 사례집에
> 열아홉 번 적어온 것과 같은 성질이다 — 결과가 맞아도 **의도한 이유로 맞은 게
> 아닐 수 있다**(사례 10).

## 한계

- **오거부 수치는 in-sample 이다.** 규칙을 이 평가셋의 실패에서 뽑았다
- **막연한 질의는 구제되지 않는다.** `"돈 되는 거 뭐 있어"`, `"3만원 이하로 살
  만한 거"` 가 경계 16건 중 막힌다. `in_domain` 불리언 하나에 **"주제 이탈" 과
  "너무 막연함" 이 눌려 있다** — 후자는 이미 `_has_target()` 이 다루는 축이다
- **에이전트 분기는 안내 문장에 기댄다.** 확정 거절이 아니라 모델의 협조가 필요하다
- `/api/anomaly/*` 는 게이트를 지나지 않는다. 거래 id 가 있어야 도는 분기라
  자연어 주제가 끼어들 자리가 없다
