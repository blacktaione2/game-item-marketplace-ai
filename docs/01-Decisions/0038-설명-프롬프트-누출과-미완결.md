# ADR-0038: 설명 프롬프트 — 필드명 누출과 미완결 문장

## 상태

채택 (2026-08-07). 배포된 화면을 눈으로 보다 잡힌 두 건이다.

## 배경

| 분기 | 사용자에게 나간 문장 |
|---|---|
| 시세 | `… 최근 120일간의 거래 이력을 바탕으로 하였으며, **cold_start가 false이므로** 유사 아이템의 추세를 반영하지 않고 …` |
| 이상거래 | `… 사용자의 실제 거래 내역과는 **번호 체계가 별개라는 점.**` |

### 둘 다 프롬프트가 시킨 대로 한 것이다

**시세**: 프롬프트가 `cold_start가 true면 …` 이라고 조건을 걸었다. 그러려면
모델이 그 필드를 읽어야 하고, **읽은 이름은 문장으로 샌다.**

**이상거래**: `max_tokens` 때문에 잘린 줄 알았는데 그런 설정은 저장소에 없다.
프롬프트의 마지막 지시가 이랬다.

```
**반드시 한 문장으로 덧붙이세요**: 이 판정은 합성 데모 거래 데이터를 대상으로
하며, 사용자의 실제 거래 내역과는 번호 체계가 별개라는 점.
```

**그 지시문 자체가 `…라는 점.` 이라는 명사형 조각**이고, 모델은 글자 하나까지
그대로 옮겨 붙였다. 잘린 게 아니라 시킨 모양이 그랬다.

## 왜 눈으로 고치지 않았는가

이 저장소는 프롬프트 한 줄 추가가 추출 정답률을 **97.5% → 22%** 로 떨어뜨린
적이 있다(`LLM-동작을-측정-없이-단정하기.md`). 원인은 "혼동하지 말라"며
**혼동 대상을 이름으로 부른 것**이었다.

그래서 이번의 자연스러운 수정 — **"필드 이름을 쓰지 마세요"라고 명시하는 것** —
이 **같은 함정일 수 있다.** 이름을 부르면 그쪽으로 유도될 수 있다.

그래서 세 안을 같이 쟀다.

| 안 | 내용 |
|---|---|
| **A** | 현재 (대조군) |
| **B** | 필드명을 **쓰지 말라고 명시** + 조건 분기를 코드로 이전 |
| **C** | 필드명을 **아예 언급하지 않음** + 페르소나("거래소 상담원") |

## 측정 설계

`scripts/evaluate_explanation_prompts.py`. **LLM 판정을 쓰지 않는다** — 아래는
전부 문자열 규칙이라 실행마다 판정이 달라지지 않는다.

- **한 실행 안에서 A/B/C.** 이전 실행 집계와 비교하면 LLM 변동이 델타를 오염시킨다.
- **도구 결과는 케이스당 한 번만 계산하고 세 안이 공유한다.** 안마다 다시
  계산하면 예측·판정 자체의 변동이 프롬프트 차이로 잡힌다.
- **케이스는 양쪽을 섞는다.** 콜드스타트 2/5, 이상 판정 3/6 — 한쪽만 모으면
  그 방향의 지표가 안 돈다.
- 케이스 11 × 안 3 × 반복 3 = **LLM 99회**.

## 결과

| 안 | n | 누출 | 미완결 | 면책누락 | 모순 | **권유** |
|---|---:|---:|---:|---:|---:|---:|
| A(현재) | 33 | **12** | **17** | 0 | 0 | 0 |
| B(명시) | 33 | **0** | **0** | 0 | 0 | 0 |
| C(미언급) | 33 | **0** | **0** | 0 | 0 | **6** |

**B 를 채택한다.** 누출·미완결이 0이고 나머지 지표가 A 보다 나빠지지 않았다.

### 우려했던 역효과는 없었다

"쓰지 말라고 이름을 부르면 오히려 쓴다"는 전례가 여기서는 **재현되지 않았다**.
B 의 누출이 0이다. 그러나 그건 **재본 뒤에 알게 된 것**이고, 안 재고 B 를
넣었다면 그게 옳았는지 알 수 없었을 것이다.

### C 는 지표가 안 재던 것으로 기각됐다

B 와 C 는 처음 넷(누출·미완결·면책누락·모순)에서 **0-0-0-0 동점**이었다.
표본을 읽어보니 C 가 이렇게 답하고 있었다.

> …앞으로의 시세는 약간 상승할 것으로 예상됩니다. **따라서, 현재 시세를
> 고려할 때 거래를 진행하는 것이 좋습니다.**

**투자 권유다.** `상담원` 페르소나가 모델을 그쪽으로 밀었다. 시세 설명의 일은
예측을 전달하는 것이지 사라 말라를 권하는 게 아니다 — 실제 거래가 붙는 화면에서
특히 그렇다. 지표를 하나 추가해 다시 채점하니 **33건 중 6건**(시세 답변 15건 중
6건)이었다.

> **동점은 "차이가 없다"가 아니라 "내 지표가 차이를 못 본다"일 수 있다.**
> 지표는 내가 생각한 것만 잰다. 표본을 읽지 않았으면 C 를 골랐을 것이고,
> 그건 결함 하나를 고치며 다른 하나를 들여오는 일이었다.

## 방법론에서 두 번 고쳤다

### 1. 모순 지표가 부정문을 못 읽었다

첫 실행에서 세 안이 **나란히 9**를 냈다. 서로 다른 프롬프트가 같은 값을 내는
것이 신호였다 — 프롬프트가 아니라 **검출기를 재고 있었다.** 정상 거래 답변이
`이상 거래로 판별되지 않았습니다` 라고 쓰는데 정규식이 `이상 거래` 만 보고
"이상이라 말했다"로 읽었다. 부정어를 읽게 고치니 0이 됐다.

> **서로 다른 입력이 같은 값을 내는 열은 입력이 아니라 지표를 재고 있다.**

### 2. 답변을 저장하지 않아 지표 수정에 99회를 다시 태웠다

첫 판본은 부르면서 바로 채점하고 답변을 버렸다. 지표가 틀린 걸 알았을 때
다시 볼 방법이 없었다.

이제 수집과 채점이 분리돼 있다(`--score-only`). 그 덕에 **권유 지표를 나중에
추가해 재채점하는 데 API 호출이 0회**였다. 이 저장소가 이미 알던 교훈인데
(같은 데이터 위에서 분할을 다시 나누는 것은 공짜다, ADR-0018) 다른 모양으로
다시 배웠다.

## 영향

| 파일 | 변경 |
|---|---|
| `app/services/assistant/pipeline.py` | 두 프롬프트 교체. `_forecast_branch` 가 콜드스타트 분기를 **코드로** 하고 완성된 지시문을 넘긴다 |
| `scripts/evaluate_explanation_prompts.py` | 신규. 수집/채점 분리, 지표 5종 |
| `data/explanation_prompt_answers.json` | 수집된 99건. 지표를 고칠 때 재사용한다 |
| `tests/test_explanation_prompts.py` | 4건. **문구가 아니라 두 결함이 안 돌아오는 성질**을 고정 |

배포될 프롬프트가 측정한 B 안과 **바이트 단위로 같은지** 확인했다 — 측정한 것과
배포한 것이 다르면 측정이 의미가 없다.

## 남은 것

- **이 지표들은 이 두 프롬프트에만 맞춰져 있다.** 검색 분기는 ADR-0036 에서
  LLM 자체를 없앴고, 에이전트 최종 설명은 아직 안 쟀다.
- `누출` 어휘 목록은 손으로 유지한다. 응답에 새 필드가 생기면 여기도 늘려야
  하는데, 그걸 강제하는 장치는 없다.
