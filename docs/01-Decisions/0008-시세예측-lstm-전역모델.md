# ADR-0008: 시세 예측은 LSTM 전역 모델 1개로 하고, 가격은 비율로 정규화한다

## 상태

채택됨

## 배경

Phase 5의 시세 예측은 계획서상 "LSTM/Transformer 시계열 예측 + Cold Start
백오프"다. 구현에 들어가면서 세 가지를 정해야 했다.

1. **구조**: LSTM인가 Transformer인가
2. **범위**: 아이템별 모델인가 전역 모델 1개인가
3. **표현**: 가격을 그대로 넣을 것인가

세 번째가 앞의 둘을 결정한다. 이 마켓의 아이템은 3,000원짜리 물약 묶음부터
850,000원짜리 만렙 계정까지 두 자릿수 배율로 흩어져 있다. 절대 가격을 그대로
학습시키면 모델이 배우는 것의 대부분이 "이 아이템은 비싼 아이템"이라는
스케일 정보가 되고, 정작 알고 싶은 "앞으로 오를 것인가"는 뒤로 밀린다.

그리고 Cold Start 요구사항이 결정적이다. 거래가 거의 없는 아이템도 예측해야
하는데, 아이템별 모델은 **그런 아이템에 대해 학습 자체가 불가능하다.**

## 결정

**1. 가격을 윈도우 마지막 값 기준 비율로 정규화한다.**

```
입력  x_t = price_t / price_last,   거래량 v_t = volume_t / mean(volume)
출력  y_h = price_(last+h) / price_last,   h = 1..7
```

모델이 배우는 것은 "며칠 뒤 몇 배가 되는가"이며 가격대와 무관해진다.

앵커를 윈도우의 **마지막 체결가** 단일 지점으로 잡은 데에는 근거가 하나
있다. 이렇게 두면 나이브 기준선(직전값 유지)의 예측이 정확히 1.0이 되어,
모델이 기준선을 이겼는지를 별도 환산 없이 바로 읽을 수 있다. 평가 편의가
표현 선택에 반영된 경우다. (노이즈 강건성 측면은 검토하지 않았다 —
아래 **알려진 한계** 참고.)

**2. LSTM을 쓴다.** 시계열 Transformer는 데이터가 많을 때 이기는 구조이고,
현재 학습 윈도우는 1,520개 규모다. 배포 대상도 Oracle Cloud ARM 4 OCPU
공유 인프라라 어텐션 비용을 낼 이유가 없다. 실제 학습은 CPU에서 40 epoch에
10초 남짓 걸린다.

**3. 아이템별이 아니라 전역 모델 1개.** 비율 정규화 덕분에 가격대가 다른
아이템을 한 배치에 섞을 수 있고, 아이템 수만큼 모델을 관리·로딩하는 부담이
사라진다. 무엇보다 이력 없는 아이템을 다룰 길이 열린다.

**4. Cold Start는 "모양은 남에게서, 수준은 자기에게서".** ES kNN으로 같은
카테고리의 이력 보유 아이템을 찾아 유사도 가중평균으로 *비율 궤적*을
물려받고, 앵커 가격만 자기 것(관측된 소수 거래의 평균, 없으면 등록가)을
쓴다. 비율 표현이 아니었다면 15만원짜리 도너의 궤적을 6만원짜리 신규
아이템에 씌울 수 없었다. 두 경로가 같은 모델·같은 피처 형태를 공유하므로
분기가 예측 로직을 복제하지 않는다.

**5. 출력은 7일치를 한 번에 내는 direct multi-step.** 하루씩 재귀 예측하면
오차가 누적되고 구현도 복잡해진다.

## 고려한 대안

1. **Transformer 시계열 모델** — 데이터 규모(아이템당 120일)와 배포 제약에
   비해 과하다. 데이터가 실거래로 쌓이면 재검토할 만하다.
2. **아이템별 개별 모델** — Cold Start 아이템에 대해 학습이 불가능해서
   요구사항 자체를 만족하지 못한다. 데이터도 아이템당 100 윈도우로 조각난다.
3. **절대 가격 그대로 학습** — 스케일 정보가 학습을 지배하고, Cold Start
   트렌드 상속이 원리적으로 성립하지 않는다.
4. **로그 수익률(log return) 표현** — 비율과 사실상 동등한 선택지다. 비율을
   고른 것은 나이브 기준선이 1.0이라는 읽기 편함 때문이고, 예측 성능상
   유의미한 차이는 기대하지 않는다.
5. **통계 모델(ARIMA/Prophet)** — 아이템마다 따로 적합해야 해서 2번과 같은
   문제를 겪고, "자체 학습 딥러닝 모델"이라는 계획서 목표에서도 벗어난다.

## 결과

- `ai/app/services/forecast/` 에 dataset / model / predictor / cold_start /
  evaluation / pipeline 으로 나뉘어 구현됐다. 학습은
  `python -m scripts.train_forecast`, 서빙은 `POST /api/forecast`.
- 검증셋(아이템별 시간순 분할, 380 윈도우) MAPE: **LSTM 4.70%**,
  나이브 직전값 유지 4.87%, 나이브 선형 외삽 7.18%.
- Cold Start 도너 선택은 의미적으로 잘 동작한다. `+9 강화 은빛 사슬갑`은
  `+9 강화 미스릴 갑옷` / `+9 강화 사슬 갑옷`을, `레벨 150 궁수 계정`은
  `만렙 전사 계정`(계정 카테고리 유일 도너, weight 1.0)을 물려받는다.
  Phase 4에서 파인튜닝한 임베딩이 여기서 재활용된다.
- 모델 아티팩트(`models/price-lstm`)는 gitignore 대상이다. 임베딩 때와 달리
  없으면 **503과 함께 실행할 명령을 알려주고** 죽는다.

## 알려진 한계

수치와 함께 반드시 같이 밝힐 것. "왜 안 했는가"가 아니라 **지금 상태가
어떤 리스크를 안고 있는가**의 기록이다.

### 1. 정규화 앵커가 단일 지점이다

입력·출력 정규화의 기준이 윈도우의 **마지막 체결가 한 건**이다. 그 한 건이
튀면 윈도우 전체의 비율과 7일치 예측이 통째로 같은 방향으로 밀린다.

합성 더미 데이터에서는 문제가 드러나지 않는다. 매일 거래가 발생하고 일별
평균가로 집계돼 있어 단일 지점이 이미 충분히 안정적이기 때문이다. **실거래로
바뀌면 상황이 달라진다** — 호가가 튄 체결 한 건, 거래가 뜸해 하루치 표본이
1~2건뿐인 날, 경매 마감 직전의 비정상 낙찰가가 그대로 앵커가 된다. 거래량이
적은 아이템일수록 위험이 크고, 그런 아이템은 Cold Start 임계값 바로 위에
몰려 있어 노출이 겹친다.

같은 코드베이스 안에 **이미 불일치가 있다.** Cold Start 경로의
`anchor_price()`는 "소수의 노이즈 있는 관측은 평균이 안정적"이라는 이유로
관측 거래의 **평균**을 쓰는데, 직접 예측 경로는 마지막 값 한 점을 쓴다.
같은 노이즈 문제를 한쪽에서만 다루고 있는 상태다.

로드맵 스트레치에 "정규화 앵커 스무딩(최근 N일 평균/중앙값) 검토"를 올려뒀다.
주의할 점: 앵커를 스무딩하면 나이브 기준선이 더 이상 1.0이 아니게 되므로
평가 코드도 같이 손봐야 한다.

### 2. 메인 예측 모델에 조건부 피처가 없다

LSTM 입력은 `[가격 비율, 거래량 비율]` 두 축뿐이다. 카테고리, 희귀도,
강화 수치, 판매 방식(고정가/경매), 요구 레벨 중 **어느 것도 모델에 들어가지
않는다.** 카테고리는 Cold Start 도너 검색의 ES 필터로만 쓰이고, 예측 모델
자체는 지금 다루는 아이템이 소모품인지 만렙 계정인지 모른다.

그래서 모델은 모든 아이템에 대해 하나의 평균적인 동역학을 적용한다. 실제로는
카테고리마다 시세 거동이 다를 것이 거의 확실하다 — 경매 아이템은 변동이 크고,
소모품은 대량 유통되며 안정적이고, 계정 거래는 표본이 희소하다. 지금 구조는
이 차이를 학습할 수단이 없어서, 변동성이 큰 아이템에서는 과소반응하고 안정적인
아이템에서는 과대반응하는 쪽으로 오차가 편향될 소지가 있다.

Cold Start에서는 이 공백이 한 겹 더 쌓인다. 도너 선택은 카테고리를 보는데
그 결과를 받는 모델은 카테고리를 모르므로, 카테고리 정보가 궤적의 모양에만
간접 반영되고 예측 함수 자체에는 전달되지 않는다.

### 3. 측정 범위의 한계

- **합성 데이터다.** MAPE 단독으로는 아무것도 증명하지 않으며, 나이브
  기준선 대비로만 판단해야 한다.
- **이벤트 급등 구간이 검증에서 빠졌다.** 급등을 데이터 후반 70% 지점에
  배치했는데 시간순 분할상 그 구간이 학습에 들어가, 검증셋은 급등 이후
  구간만 본다. 스파이크 예측력은 아직 측정되지 않았다.
- **단일 실행이다.** 시드 분산을 재지 않았다.
