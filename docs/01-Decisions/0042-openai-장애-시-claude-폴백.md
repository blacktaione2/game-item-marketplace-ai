# ADR-0042: OpenAI 장애 시 Claude 로 넘긴다 — 서킷 브레이커 포함

## 상태

채택 (2026-08-08). ADR-0004 가 *"서킷 브레이커 뒤의 진짜 폴백 대상"* 이라고 적어둔
것을 실제로 만들었다. **정적 안내문이 아니라 다른 LLM 이 답한다.**

## 배경 — 내가 "키가 없다" 고 단정했고 틀렸다

ADR-0041 은 이 항목을 미룬 이유를 *"API 키가 없어 경로를 밟아볼 수 없다"* 로 적었다.
**확인하지 않고 한 말이었다.** 사용자가 알려줘서 보니 키는 있었다.

그런데 확인해보니 **폴백이 지금 상태로는 동작할 수 없는 이유**도 같이 나왔다.

| 파일 | `ANTHROPIC_API_KEY` |
|---|---|
| 저장소 루트 `.env` | **있음** |
| `ai/.env` | **없음** |

CLAUDE.md 가 이미 적어둔 함정이다 — *루트 `.env` 는 docker-compose 용이고 FastAPI
앱은 `ai/.env` 를 읽는다.* 게다가 코드에 `anthropic` 을 쓰는 곳이 0건이었으므로
**키가 어디 있든 아무 일도 일어나지 않았다.**

> **환경에 대한 주장은 확인하고 해야 한다.** "없다" 는 "안 봤다" 와 다르다. 이
> 저장소가 반복해서 적어온 *"밟히지 않은 경로는 동작한다고 말할 수 없다"* 의
> 짝이다 — 보지 않은 파일은 비어 있다고 말할 수 없다.

## 결정 1 — 이 파일의 대부분은 **형식 번역**이다

`LLMClient` 는 중립 인터페이스인데, 그 위의 **에이전트 루프가 OpenAI 메시지 형식을
그대로 쓴다**(`{"role": "tool", "tool_call_id": ...}`).

> **인터페이스만 맞추고 형식을 안 맞추면 `complete()` 는 되고 에이전트만 조용히
> 깨진다** — 폴백이 가장 필요한 순간에. 그리고 단위 테스트로는 안 보인다.

| OpenAI | Anthropic |
|---|---|
| `{"role": "system"}` 메시지 | **최상위 `system` 파라미터** |
| `assistant` + `tool_calls[]` | `content` 안의 `tool_use` 블록 |
| `{"role": "tool", "tool_call_id"}` | `user` 메시지 안의 `tool_result` 블록 |
| `{"type": "function", "function": {…, "parameters"}}` | `{name, description, input_schema}` |
| `max_tokens` 선택 | **필수** |

**연속된 도구 결과는 한 메시지로 합친다.** Anthropic 은 역할이 번갈아 나오길
기대하므로 안 합치면 400 이다 — **도구를 하나만 부르는 동안에는 안 보이다가 둘을
부르는 순간 터지는** 종류다. 테스트가 이걸 따로 고정한다.

## 결정 2 — 서킷 브레이커를 둔다. 새 의존성 없이

예외만 잡아 넘기면 장애 동안 **모든 요청이 OpenAI 타임아웃을 먼저 물고** 폴백으로
간다.

> 이 저장소는 그 대가를 이미 치렀다. RabbitMQ publish 를 fail-open 으로 감쌌는데
> AMQP 기본 연결 타임아웃이 60초라 **"구매는 성공하는데 1분 걸린다"** 가 됐다
> (ADR-0030). **fail-open 에는 정합성 축 말고 지연 축이 있다.**

연속 실패 3회면 60초 동안 1차를 건너뛴다. `pybreaker` 를 들이지 않은 것은 백엔드가
Redisson `RRateLimiter` 를, AI 서버가 `redis.asyncio` 를 **이미 가진 것으로** 한도를
만든 것과 같은 판단이다(ADR-0024). 필요한 것은 카운터 하나와 타임스탬프 하나다.

**반열림 상태를 따로 두지 않는다.** 리셋창이 지나면 그냥 닫고, 카운터를 임계값
직전으로 되돌린다 — 다음 요청 하나가 탐침이 되고 그게 실패하면 즉시 다시 열린다.
상태를 하나 더 두는 값어치가 없다.

**프로세스 내 상태다.** 인스턴스가 여럿이면 각자 배운다. Redis 로 공유할 수도
있지만 이건 비용·정합성이 아니라 *"이 프로세스가 방금 겪은 일"* 이고, 공유하면
Redis 장애가 LLM 경로를 물게 된다.

## 결정 3 — 둘 다 죽으면 **1차 예외**를 올린다

2차의 예외로 바꿔치면 진단이 엉뚱한 곳을 가리킨다. 1차가 죽어서 시작된 일인데
로그에는 Anthropic 오류만 남는다. 그 위에서 **ADR-0041 의 내려앉기가 받는다** —
두 겹이 순서대로 선다.

```
OpenAI 실패 -> Claude 폴백 -> (둘 다 실패) -> 결정적 문장 -> (그것도 아니면) 500
```

## 결정 4 — 키가 없으면 폴백을 **만들지 않는다**

없는 폴백을 있는 척 감싸면 장애가 나서야 "폴백이 없었다" 를 알게 된다. 어느
쪽이든 기동 로그에 남기고, 없을 때는 **어느 파일에 넣어야 하는지까지** 적는다 —
이 라운드가 정확히 그 실수에서 시작했기 때문이다.

> **정정 (배포 후): "어느 쪽이든 기동 로그에 남는다" 가 틀렸다.** 둘 다
> `logger.info` 로 썼는데 **이 앱은 로깅을 설정하지 않는다** — 파이썬 루트
> 로거 기본값이 `WARNING` 이라 그 줄은 어디에도 안 나온다. 배포 후
> `docker logs | grep` 이 빈 결과를 냈고, 그건 **"폴백이 없다" 와 "로그가
> 안 보인다" 를 구분해주지 못했다.**
>
> 고친 것 둘: **없음 = `warning`**(레벨도 내용상 맞다 — 약화된 구성이다),
> 그리고 **`/health` 에 `llm_fallback` 을 실어** 로그 레벨에 기대지 않고
> 확인할 수 있게 했다. 키 자체는 안 싣는다(구성 여부 bool 만).
>
> **로그로 확인하라고 안내하려면 그 레벨이 실제로 출력되는지부터 확인해야
> 한다.** "판정에 쓴 값을 출력에 넣어라" 의 인프라 버전이다 — 값을 넣어도
> 통로가 막혀 있으면 없는 것과 같다.

폴백의 `temperature` 는 1차와 같은 값이다. **폴백이 더 흔들리면 장애 때 답이 더
나빠진다** — 목적과 정반대다(ADR-0017).

## 실제로 밟아봤다 — 다섯 가지

`ai/.env` 에 키를 옮기고 **진짜 Claude 호출로** 확인했다. ADR-0039 에서 MCP
안내문이 한 번도 안 밟힌 채 넘어갔던 일을 되풀이하지 않으려고 항목을 나눴다.

| | 확인한 것 | 결과 |
|---|---|---|
| 1 | Claude 단독 호출 | `"서울"` |
| 2 | 1차를 죽이고 폴백이 받는가 | `"서울"` |
| 3 | 임계값에서 서킷이 열려 1차를 **안 부르는가** | 5회 요청 중 1차 호출 **3회** |
| 4 | **질의이해 JSON 이 폴백에서 파싱되는가** | `element=화염 subcategory=검 price_max=30000` |
| 5 | **에이전트 도구 호출이 폴백에서 되는가** | `search_items(tenant_code, query)` |

4번과 5번이 이 라운드의 진짜 위험이었다. 1~3번만 보고 끝냈으면 *"폴백은 되는데
검색과 에이전트만 안 되는"* 상태를 채택할 뻔했다.

## 영향

- `requirements.txt` 에 `anthropic>=0.40`. **주석은 ASCII 로 썼다** — pip 이 시스템
  로케일 코덱으로 읽어서 한글이 들어가면 cp949 에서 설치가 깨진다
- `ANTHROPIC_API_KEY` / `ANTHROPIC_MODEL` 은 **`ai/.env`** 다. compose 의 `ai`·
  `ai-init` 서비스가 `env_file: ./ai/.env` 를 쓰므로 **이 한 곳이 로컬과 컨테이너를
  둘 다 덮는다.** 루트 `.env` 에 넣으면 아무 일도 일어나지 않는다
- **배포 서버의 `ai/.env` 에도 넣어야 한다.** 안 넣으면 기동 로그에 "폴백 없음" 이
  남고 동작은 지금과 같다(조용히 깨지지는 않는다)
- 테스트 228 → **248** (20건 추가, 네트워크 없이 돈다)
- 비용: 평시 0 — **1차가 성공하면 2차를 아예 안 부른다**

## 남은 것

- **백엔드 Resilience4j 는 여전히 없다.** 계획서의 서킷 브레이커는 AI 호출 경로를
  말한 것이고 그건 이 ADR 로 됐지만, 백엔드→AI 호출(`/api/health` 프록시)에는
  아무것도 없다. 다만 그 경로는 지금 헬스체크뿐이라 급하지 않다
- ~~서킷 상태를 메트릭으로 내보내지 않는다~~ → **같은 날 보완했다. 다만 처음 적은
  이유는 틀렸다.** "어디에도 안 남는다" 가 아니라 `logger.warning` 으로 **남기는
  하고 집계가 안 됐다.** 그 이유만으로는 약하다 — Prometheus 는 `--profile
  observability` 옵트인이라 평소에 돌지도 않는다.

  **진짜 이유는 이 ADR 이 기존 지표를 모호하게 만든 것이다.**
  `ai_llm_calls_total` 은 *"이 요청이 LLM 을 몇 번 썼나"* 인데, 프로바이더가
  하나일 땐 그게 곧 OpenAI 사용량이었다. **폴백이 붙는 순간 그 해석이 깨졌고**
  어디에 청구됐는지 말해주지 않는다. 새 기능이 아니라 **내가 만든 드리프트**다.

  `ai_llm_provider_calls_total{provider, outcome}` 을 더했다. 설계 셋:

  - **계측을 각 클라이언트 안에 둔다.** 폴백 래퍼에 두면 **키가 없는 구성에서
    아무것도 안 잡힌다** — 정작 프로바이더가 하나뿐이라 더 취약한 쪽이다
  - **`record_response()` 로는 표현이 불가능하다.** 에이전트 한 요청이 `chat()`
    을 다섯 번 부르고 그중 둘만 폴백일 수 있다 — 이 사실은 **응답 모양이
    아니다.** 계측점 원칙의 두 번째 예외이고, `rate_limited_total` 이 그랬듯
    예외인 이유를 코드에 적어뒀다
  - **`tenant` 라벨을 넣지 않는다.** 프로바이더 장애는 테넌트와 무관하다

  덤: `ai_llm_calls_total` 은 응답의 `llm_calls` **상수**에서 오고 새 카운터는
  **실제 호출**을 센다 — **둘이 어긋나면 그 상수가 틀린 것**이다. ADR-0039·0041
  에서 그 값을 세 번 손으로 고쳤으니 교차 검증이 생긴 셈이다
- 게이지(서킷 open 여부)는 **안 만들었다.** 카운터에서 읽힌다(1차 실패 급증 →
  1차 호출 0). 볼 대시보드가 없는 상태에서 표면을 늘리지 않는다
