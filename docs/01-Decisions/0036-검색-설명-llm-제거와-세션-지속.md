# ADR-0036: 검색 설명 LLM 제거, 그리고 세션을 sessionStorage 로

## 상태

채택 (2026-08-07). 배포된 서비스를 브라우저로 써보다 나온 두 건이다.

## 배경

### 1. 검색 설명이 결과를 부정했다

`10만원 이하 검 찾아줘` 질의에 **네 건이 나왔다.**

| 이름 | 가격 | subcategory |
|---|---|---|
| 미스릴 단검 | 22,000원 | 검 |
| +9 강화 롱소드 | 45,000원 | 검 |
| +8 강화 롱소드 | 28,000원 | 검 |
| +7 강화 롱소드 | 15,000원 | 검 |

그런데 답변은 이랬다.

> 사용자의 요청에 맞는 10만원 이하의 검 아이템은 **없습니다**. 검색 결과에는
> 다양한 가격대의 롱소드와 단검이 포함되어 있지만, 모두 10만원을 초과하거나
> **검이 아닌 무기**입니다.

**두 주장이 다 거짓이다.** 네 건 모두 10만원 이하이고 네 건 모두 `subcategory="검"`이다.
화면에는 그 카드 넷이 답변 바로 아래에 나란히 떠 있었다.

#### 원인 — 프롬프트가 끝난 판정을 다시 시킨다

```python
_SEARCH_PROMPT = """... 질의와 종류가 맞지 않는 항목이 섞여 있으면
그 항목은 빼고 말하세요. ..."""

def _brief(results):
    return [{"name": ..., "category": ..., "price": ...} for doc in results]
    #                     ^^^^^^^^^^^^ subcategory 가 없다
```

LLM 이 받은 건 네 건 모두 `category: "무기"` 다. **종류를 판단하라는 지시를
받았는데 종류를 가리는 필드가 페이로드에 없다.**

그 지시는 **화석**이다. 하드 필터가 없던 시절엔 카테고리 혼입이 실제로 UI 에
보였다(`단궁`이 `검` 검색에 섞이던 문제). ADR-0014·0015 가 `subcategory`·
`element` 를 ES `term` 절로 거르면서 그 일은 끝났고, 가격도 필터가 처리한다.
**필터가 이미 정확히 한 일을, 필터보다 적은 정보로 LLM 에게 다시 시키고
있었다.**

가격 주장까지 틀린 건 그 위에 얹힌 별개 환각이다. 지시가 "뭔가 걸러내라"는
쪽으로 밀어붙이면, 걸러낼 게 없을 때 **없는 근거를 만든다.**

### 2. 새로고침하면 로그아웃된다

`/items/5` 에서 F5 를 누르면 로그인 화면으로 간다. SPA 폴백은 정상이고
(200 으로 앱을 내려준다), 세션이 메모리에만 있어서 그렇다 — ADR-0031 의 결정이다.

> localStorage 에 넣으면 XSS 한 번에 토큰이 새므로, 데모 편의를 위해 그 위험을
> 지지 않는다.

논리는 맞는데 **양자택일이 아니었다.**

## 결정

### 1. 검색 분기의 설명 LLM 을 제거한다

결과가 있을 때도 0건과 **같은 방식**으로 확정 문장을 만든다.

```python
def _search_answer(filters, count):
    conditions = _describe_filters(filters)      # _no_results 와 같은 함수
    if conditions:
        return f"{' · '.join(conditions)} 조건으로 {count}건 찾았습니다."
    return f"검색 결과 {count}건입니다."
```

`검 · 100,000원 이하 조건으로 4건 찾았습니다.`

`_SEARCH_PROMPT` 와 `_brief` 는 **삭제**한다. 남겨두면 "되살리면 되지"로
읽히는데, 되살릴 값어치가 없다는 게 이 결정의 내용이다.

**검색 분기 `llm_calls` 가 2 → 1 이 된다.** 남는 하나는 `understand_query` 이고
건너뛸 수 없다 — 필터를 뽑는 그 호출이다.

### 2. 세션을 `sessionStorage` 에 둔다

```tsx
const SESSION_KEY = "gimp.session";
const restoredSession = loadSession();   // 모듈 로드 시 1회
```

로그아웃·만료·복원 실패 **세 곳 전부**에서 저장소를 비운다.

## 고려한 대안

### 검색 설명

| 안 | 왜 안 골랐나 |
|---|---|
| **프롬프트만 수정** (재판정 지시 삭제 + `subcategory` 추가) | 이번 환각은 막았겠지만 환각 *부류*는 남는다. 그리고 **더할 정보가 없다** — 카드가 이미 이름·가격·종류·속성을 전부 보여준다. 위험만 남고 이득이 없는 호출이다 |
| **조건부 설명** (필요할 때만 LLM) | "언제 필요한가"의 판정 규칙을 새로 설계해야 한다. 그 규칙이 틀리면 같은 문제가 조건부로 재현된다 |
| 프롬프트에 "결과 수를 부정하지 말라" 추가 | **프롬프트로 사실을 보장할 수 없다.** 이 저장소는 그 교훈을 이미 비싸게 샀다 — 한 줄 추가가 추출 정확도를 97.5% → 22% 로 떨어뜨린 적이 있다 |

### 세션

| 안 | 왜 안 골랐나 |
|---|---|
| **메모리 유지** (현행) | 데모에서 새로고침 한 번에 로그아웃. 포트폴리오로 못 쓴다 |
| **localStorage** | 탭을 닫아도 살아남고 탭 간에 공유된다. ADR-0031 이 거부한 게 바로 이 지속성이다 |
| **리프레시 토큰** (httpOnly 쿠키) | 제대로 된 방식이지만 새 엔드포인트 + 저장소 + 회전 정책 + CSRF 대응이 따라온다. 이 라운드 크기를 넘는다 |

`sessionStorage` 를 고른 근거는 **잃는 게 작다**는 것이다. XSS 가 나면
**메모리의 토큰도 그 자리에서 빼간다** — 공격자가 이미 페이지 안에서 JS 를
돌리고 있기 때문이다. 실질적 차이는 `localStorage` 와의 사이에 있고, 그건 그대로
피한다.

## 영향

### 코드

| 파일 | 변경 |
|---|---|
| `ai/app/services/assistant/pipeline.py` | `_SEARCH_PROMPT`·`_brief` 삭제, `_search_answer` 추가, 검색 분기 `llm_calls` 2 → 1 |
| `ai/tests/test_no_results.py` | `TestSearchAnswer` 4건. **"결과가 있는데 없다고 말하지 않는다"를 단언한다** |
| `frontend/src/App.tsx` | `sessionStorage` 복원·저장·삭제 (세 자리) |
| `load/verify-container.sh` | 판정 1-b 가 `no_results` 를 같이 읽는다 (아래) |

### 검사 하나가 이 변경으로 틀리게 된다

판정 1-b 의 실패 메시지가 *"1회차 `llm_calls` 가 1 이면 검색 0건"* 이라고
적고 있었다. 검색이 0건이든 아니든 1 이 되므로 **그 구분이 사라진다.** 응답의
`no_results` 를 직접 읽게 바꿨다.

> 같은 라운드에서 만든 검사가 같은 라운드의 다음 변경으로 낡았다. **호출 수처럼
> 파생된 값을 판정 근거로 쓰면, 그 값을 만드는 쪽이 바뀔 때 조용히 틀린다.**
> 사실을 직접 말하는 필드가 있으면 그쪽을 읽는다.

> **[2026-08-07] 그 교훈이 한 번 더 입증됐다.** ADR-0039 가 도메인 판정을 병렬
> 호출로 추가하면서 **검색 분기의 `llm_calls` 가 1 → 2 로 또 바뀌었다**(시세는 3).
> 위에서 `no_results` 를 직접 읽게 바꿔둔 덕에 판정 1-b 는 이번엔 안 깨졌다.
> 변하지 않은 성질은 **"분기 안에서 무슨 일이 있었든 같은 값"** 이라는 것뿐이다.

### 남는 것

- **LLM 설명은 나머지 세 분기(시세·이상거래·복합)에 그대로 있다.** 파이프라인의
  "LLM 이 설명을 생성한다"는 성질은 유지되고, **정보를 더하지 않는 자리에서만**
  뺐다.
- 시세 분기의 `cold_start가 false이므로` 같은 **내부 필드명 노출은 아직 남아
  있다.** 같은 부류지만 프롬프트 수정이 필요하고, 그건 측정 없이 하지 않는다
  (`도구-출력-필드명-모호성.md` 참고). 별도 라운드로 등록한다.
- `explain_ms` 가 검색 분기에서 사라진다. ADR-0019 가 처음 계측한 값인데, 그
  계측이 있었기에 **이 호출의 비용을 알고 지울 수 있었다.**
