# ADR-0041: 설명 LLM 이 죽으면 500 대신 결정적 문장으로 내려앉는다

## 상태

채택 (2026-08-08). **계획서의 서킷브레이커 항목 중 지금 검증 가능한 절반**이다 —
Claude 폴백은 하지 않았고, 그 이유는 아래 「하지 않은 것」에 적었다.

## 배경 — 장애 시 동작이 비대칭이었다

`circuit`·`resilience`·`fallback` 을 코드에서 찾으면 **0건**이다. OpenAI 가 죽으면
분기마다 다른 일이 일어난다.

| 분기 | 지금 | 왜 |
|---|---|---|
| 검색 | **산다** (성능 저하) | `understand_query` 가 원본 질의로 폴백, 게이트는 fail-open |
| FAQ | 산다 | LLM 을 안 부른다 |
| **시세 · 이상거래** | **500** | 설명 호출이 터지고 포괄 예외가 받는다 |
| 에이전트 | **500** | LLM 이 곧 분기다 |

**검색이 사는 것은 설계된 게 아니라 fail-open 두 개가 우연히 겹친 결과**다. 그리고
시세·이상거래에는 아무 방어가 없었다.

### 그 시점에 답은 이미 손에 있었다

이게 결정의 핵심이다. 설명 호출이 터지는 순간

- 시세 분기는 `forecast_price()` 결과를 **이미 갖고 있다** — 이름·기준가·기간·
  변동률·콜드스타트 여부
- 이상거래 분기는 판정과 기여도를 **이미 계산해뒀다**

**없는 것은 산문뿐인데 500 을 냈다.** 사용자는 계산이 다 끝난 답을 못 받는다.

## 결정 1 — 폴백은 결정적 문장이다

ADR-0036 이 검색 분기에서 한 것과 **같은 처방**이다: 결정 단계가 이미 가진 값으로
문장을 만든다. 거기서는 그게 주 경로였고 여기서는 폴백이라는 것만 다르다.

```python
answer, explain_ms, degraded = await _timed_complete(
    llm_client, prompt, lambda: _forecast_answer(result)
)
```

**폴백을 값이 아니라 콜러블로 받는다.** 값으로 받으면 성공 경로에서도 매번 문장을
만들게 되고, 쓰지도 않을 것을 계산한다. 테스트가 이걸 고정한다.

세 가지가 그 문장에 실린다.

- **사과하지 않는다.** 사용자가 물은 것에 대한 답은 전부 들어 있다. `degraded` 는
  운영자가 보는 값이지 사용자에게 할 말이 아니다
- **프롬프트가 조건부로 붙이던 고지를 그대로 붙인다** — 콜드스타트 추정이라는 것,
  이상거래 판정이 합성 코퍼스라는 것. 빠지면 **모델이 살아 있을 때만 정직한**
  응답이 된다
- **질의를 받지 않는다.** `_forecast_answer(result)` 는 결과만 본다 — ADR-0039 가
  설명 프롬프트에서 질의를 뺀 것과 같은 보장이 시그니처로 걸린다

## 결정 2 — `llm_calls` 를 줄이고 `degraded` 를 싣는다

내려앉으면 그 호출은 **성사되지 않았다.** 시세 분기 `llm_calls` 는 3 → **2**,
이상거래는 1 → **0** 이다. 안 줄이면 비용 지표가 안 나간 돈을 세게 된다.

그리고 조용히 넘기지 않는다 — `outcome="degraded"` 라는 자기 열을 준다.

> **500 이 안 나므로 다른 데서는 안 보인다.** 사용자는 답을 받았으니 실패가
> 아니지만 `ok` 도 아니다. 이 값이 늘면 프로바이더가 흔들리고 있다는 뜻이고, 그건
> 이 열이 없으면 **아무 신호도 남기지 않는다.** `core/rate_limit.py` 가 세운
> 규칙 그대로다: 열되 기록한다.

에이전트 분기는 손대지 않았다. 거기서는 **LLM 이 곧 분기**라 내려앉을 자리가 없다.
정직한 500 이 맞다.

## 결정 3 — 500 이 예외 문자열을 내보내지 않는다

라운드를 준비하다 찾았다.

```python
raise HTTPException(status_code=500, detail=f"요청 처리 실패: {e}")
```

업스트림 메시지에는 ES 인덱스명·쿼리 DSL·내부 호스트가 섞여 나온다. 백엔드는
`server.error.include-stacktrace: never` 로 같은 자세를 **처음부터** 취하고 있었고
AI 서버만 안 맞춰져 있었다.

> **한쪽만 선언된 설정은 결정이 아니라 누락이다.** `REDIS_PASSWORD` 가 백엔드에만
> 있었던 것과 같은 모양이다.

그리고 **하나만 고치면 안 됐다.** 훑어보니 **다섯 라우터 중 다섯이 전부** 그렇게
쓰고 있었다. 하나 고치고 말았다면 사례집이 이미 적어둔 *"같은 파일 안에서 같은
실수가 반복됐다"* 를 또 반복했을 것이다.

전부 일반 메시지로 바꾸고 **서버에는 `logger.exception` 으로 남긴다** — 안 남기면
진단 수단이 같이 사라진다. `tests/test_error_detail_leak.py` 가 소스를 훑어
고정한다(라우터마다 손으로 쓰는 규칙은 잊으면 조용하다). 그 검사 자체가 헛돌지
않는지도 **일부러 틀린 문자열로** 확인한다.

## 하지 않은 것 — Claude 폴백

계획서(ADR-0004)는 Claude 를 *"Resilience4j 서킷브레이커 뒤의 진짜 폴백 대상"* 으로
적어뒀다. **이번에 하지 않았다.**

**API 키가 없어 경로를 밟아볼 수 없기 때문이다.**

> **정정 (같은 날, ADR-0042): 이 문장이 틀렸다.** 키는 저장소 루트 `.env` 에
> 있었고, 나는 **확인하지 않고 없다고 단정했다.** 다만 `ai/.env` 에는 없어서
> 앱이 읽지 못하는 상태였던 것은 맞다 — 그래서 결론("지금은 동작 안 한다")은
> 우연히 맞고 근거는 틀렸다. 폴백은 ADR-0042 로 만들었고 실제 호출로 밟았다.
> **"없다" 는 "안 봤다" 와 다르다.** 배선만 해두고 "됐다" 고 적는 것은
이 저장소가 ADR-0039 에서 값을 치른 실수다 — MCP 안내문이 그 라운드에서 한 번도
안 밟혔고, 그래서 도구를 직접 불러 따로 확인해야 했다.

> **밟히지 않은 경로는 동작한다고 말할 수 없다.**

그리고 순서가 이쪽이 맞다. 폴백 프로바이더가 생겨도 **양쪽이 다 죽는 경우**는
남고, 그때 필요한 것이 지금 만든 내려앉기다. 서킷브레이커는 이 위에 얹는다.

## 고려한 대안

| 대안 | 왜 안 했나 |
|---|---|
| 재시도 | 프로바이더 장애에는 지연만 늘린다. 요청 스레드에서 기다리는 대가는 RabbitMQ 라운드에서 이미 겪었다(기본 연결 타임아웃 60초) |
| 정적 안내문 (`"일시적인 오류입니다"`) | 계산이 끝난 답을 버린다. ADR-0004 가 명시적으로 원치 않은 것 |
| 500 을 그대로 두고 화면에서 처리 | 답이 있는데 안 주는 건 같다. 그리고 프론트가 분기마다 다르게 처리해야 한다 |
| 서킷브레이커 먼저 | 열려 있는 동안 **무엇을 돌려줄지**가 먼저 정해져야 한다. 그게 이 ADR 이다 |

## 영향

- `_timed_complete` 가 `(answer, ms, degraded)` 3-튜플을 준다. 호출자 둘 다 갱신
- 새 결정적 문장 `_forecast_answer` / `_anomaly_answer` — `_search_answer`·
  `_no_results` 와 같은 자리, 같은 방식
- `outcome="degraded"` 신규. 메트릭 계측점은 여전히 `record_response()` 하나다
- 라우터 5개의 500 응답이 일반 메시지로 바뀐다. **오류 본문을 파싱하던 것이
  있으면 깨진다** — 훑어봤고 없다
- 테스트 203 → **228** (25건 추가, 전부 LLM 없이 돈다)
- 남은 것: **서킷브레이커 + Claude 폴백** (키가 있어야 밟을 수 있다),
  에이전트 분기의 장애 대응
