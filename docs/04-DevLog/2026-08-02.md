# 2026-08-02 — 동기 CPU 호출을 루프 밖으로 (ADR-0028)

로드맵에 `asyncio.to_thread`로 등록해둔 항목. **등록 내용이 세 군데 틀려서**
착수 전 격리 측정이 설계를 다시 쓰게 만들었다.

## 착수 전 측정이 뒤집은 것

| 등록된 내용 | 실측 |
|---|---|
| 대상은 임베딩·리랭커·KoELECTRA·**오토인코더** | 오토인코더 0.31ms, LSTM 0.45ms — **왕복 비용(0.211ms)과 같은 자리수**. 대상이 아니다 |
| 근거는 `encode_one` **15.77ms** | 같은 요청의 `rerank`가 **103~189ms**로 4~5배. 주범을 안 보고 있었다 |
| `asyncio.to_thread`로 옮긴다 | 기본 실행기 크기(개발기 16 / 대상 8)가 **손해 구간**. torch는 워커 4에서 **+85% 느려진다** |

목록에 없던 것도 하나 나왔다 — `build_timeline()`이 **최초 1회 2.3~3.4초**
루프를 멈춘다. 그런데 `/api/anomaly/*`는 핸들러가 `async def`가 아니라 `def`라
FastAPI가 이미 스레드로 넘기고 있었고, **`/api/assistant` 경로만** 노출돼 있었다.
같은 함수가 진입점에 따라 다르게 동작하고 있었던 셈이다.

## 한 것

- `app/core/threadpool.py` — `ThreadPoolExecutor(max_workers=2)` + `run_cpu()`.
  단일 이음매
- 호출 지점 전환: `search/pipeline`(encode, rerank), `assistant/pipeline`
  (embed, route, detect_trade), `forecast/cold_start`(encode)
- `semantic_cache.lookup()`의 임베딩 콜러블이 async가 됐다. **정확 일치면
  호출 자체가 없다**는 ADR-0026의 성질은 그대로

풀 크기 2의 근거는 워커 수를 바꿔가며 잰 표다 — 검색 1건(encode+rerank) 기준
워커 2는 −134ms 이득, 워커 4는 +119ms 손해.

## 판정선 하나가 실패했다 — 그리고 판정선 쪽이 틀렸다

측정 전에 세 개를 걸었다. **1번이 실패했다.**

> `live-llm` 3VU 중 티커 **최대 지연 < 20ms**

같은 코드로 두 번 쟀는데 **32.75ms(실패)와 17.89ms(통과)** 가 나왔다. 나중에
잰 유휴 대조군이 원인을 말해줬다 — **부하 0인 서버가 이미 max 16.34ms**다
(Windows 타이머 분해능). 판정선은 잡음 바닥 위에 3.66ms만 남겨두고 있었고,
하필 3,600표본 중 하나로 결정되는 `max`에 걸려 있었다.

**판정선을 고쳐 통과시키지 않았다.** 실패로 기록하고, 흔들리지 않은 두 값으로
채택 판단을 했다:

| | 유휴 | 변경 전 | 후 #1 | 후 #2 |
|---|---:|---:|---:|---:|
| p99 | 6.68 | 29.33 | 11.88 | 10.65 |
| 20ms 초과 | 0 | 49 | 1 | 0 |

나머지 둘은 통과했다.

- **판정선 2** — 풀 페널티. 같은 프로세스에서 **A-B-A-B로 교대** 측정
  (`encode_one` −3.0%, `rerank` −1.0%). 격리값을 기준으로 안 쓴 이유는 이
  기계의 세션 간 편차가 커서다(같은 항목이 103ms와 189ms)
- **판정선 3** — 적중 경로 불변. **코드를 되돌려가며 같은 세션에서** 쟀다:
  436.56 → 436.93 req/s, p95 26.23 → 24.92ms. `cache_encode` 관측 수는 적중
  4,578건 동안 4.0 → 4.0

## 얻은 것을 정확히 적으면

**처리량은 안 늘었고 늘 것으로 약속하지도 않았다.** 스레드로 옮긴다고 CPU
작업이 빨라지지 않는다 — torch는 오히려 동시 실행에서 느려진다. 얻은 것은
루프 응답성 하나이고 판정선도 거기에 걸었다.

부수 효과 하나는 실질적이다: `agent_tool_timeout_seconds` 주석이 "로딩이
동기라 루프를 막는 동안은 타임아웃이 발동조차 못 한다"고 적혀 있었는데,
**그 경로에 한해 이제 발동할 수 있다.**
