# 2026-08-02 — 동기 CPU 호출을 루프 밖으로 (ADR-0028)

로드맵에 `asyncio.to_thread`로 등록해둔 항목. **등록 내용이 세 군데 틀려서**
착수 전 격리 측정이 설계를 다시 쓰게 만들었다.

## 착수 전 측정이 뒤집은 것

| 등록된 내용 | 실측 |
|---|---|
| 대상은 임베딩·리랭커·KoELECTRA·**오토인코더** | 오토인코더 0.31ms, LSTM 0.45ms — **왕복 비용(0.211ms)과 같은 자리수**. 대상이 아니다 |
| 근거는 `encode_one` **15.77ms** | 같은 요청의 `rerank`가 **103~189ms**로 4~5배. 주범을 안 보고 있었다 |
| `asyncio.to_thread`로 옮긴다 | 기본 실행기 크기(개발기 16 / 대상 8)가 **손해 구간**. torch는 워커 4에서 **+85% 느려진다** |

목록에 없던 것도 하나 나왔다 — `build_timeline()`이 **최초 1회 2.3~3.4초**
루프를 멈춘다. 그런데 `/api/anomaly/*`는 핸들러가 `async def`가 아니라 `def`라
FastAPI가 이미 스레드로 넘기고 있었고, **`/api/assistant` 경로만** 노출돼 있었다.
같은 함수가 진입점에 따라 다르게 동작하고 있었던 셈이다.

## 한 것

- `app/core/threadpool.py` — `ThreadPoolExecutor(max_workers=2)` + `run_cpu()`.
  단일 이음매
- 호출 지점 전환: `search/pipeline`(encode, rerank), `assistant/pipeline`
  (embed, route, detect_trade), `forecast/cold_start`(encode)
- `semantic_cache.lookup()`의 임베딩 콜러블이 async가 됐다. **정확 일치면
  호출 자체가 없다**는 ADR-0026의 성질은 그대로

풀 크기 2의 근거는 워커 수를 바꿔가며 잰 표다 — 검색 1건(encode+rerank) 기준
워커 2는 −134ms 이득, 워커 4는 +119ms 손해.

## 판정선 하나가 실패했다 — 그리고 판정선 쪽이 틀렸다

측정 전에 세 개를 걸었다. **1번이 실패했다.**

> `live-llm` 3VU 중 티커 **최대 지연 < 20ms**

같은 코드로 두 번 쟀는데 **32.75ms(실패)와 17.89ms(통과)** 가 나왔다. 나중에
잰 유휴 대조군이 원인을 말해줬다 — **부하 0인 서버가 이미 max 16.34ms**다
(Windows 타이머 분해능). 판정선은 잡음 바닥 위에 3.66ms만 남겨두고 있었고,
하필 3,600표본 중 하나로 결정되는 `max`에 걸려 있었다.

**판정선을 고쳐 통과시키지 않았다.** 실패로 기록하고, 흔들리지 않은 두 값으로
채택 판단을 했다:

| | 유휴 | 변경 전 | 후 #1 | 후 #2 |
|---|---:|---:|---:|---:|
| p99 | 6.68 | 29.33 | 11.88 | 10.65 |
| 20ms 초과 | 0 | 49 | 1 | 0 |

나머지 둘은 통과했다.

- **판정선 2** — 풀 페널티. 같은 프로세스에서 **A-B-A-B로 교대** 측정
  (`encode_one` −3.0%, `rerank` −1.0%). 격리값을 기준으로 안 쓴 이유는 이
  기계의 세션 간 편차가 커서다(같은 항목이 103ms와 189ms)
- **판정선 3** — 적중 경로 불변. **코드를 되돌려가며 같은 세션에서** 쟀다:
  436.56 → 436.93 req/s, p95 26.23 → 24.92ms. `cache_encode` 관측 수는 적중
  4,578건 동안 4.0 → 4.0

## 얻은 것을 정확히 적으면

**처리량은 안 늘었고 늘 것으로 약속하지도 않았다.** 스레드로 옮긴다고 CPU
작업이 빨라지지 않는다 — torch는 오히려 동시 실행에서 느려진다. 얻은 것은
루프 응답성 하나이고 판정선도 거기에 걸었다.

부수 효과 하나는 실질적이다: `agent_tool_timeout_seconds` 주석이 "로딩이
동기라 루프를 막는 동안은 타임아웃이 발동조차 못 한다"고 적혀 있었는데,
**그 경로에 한해 이제 발동할 수 있다.**

## 발표자료 (`docs/06-발표/`)

기술 면접관 10분 기준, 슬라이드 14장 + 발표 노트(시간 배분·예상 질문 7개).

- **자체 완결 HTML**(외부 요청 0, 29KB). 발표장 와이파이를 전제하지 않으려고
  reveal.js를 안 넣었고, 그럼에도 `git diff`가 되는 텍스트여야 해서 마크다운이
  아니라 HTML이다. `P`로 슬라이드당 한 페이지 PDF가 나온다
- 구성이 **개선 6 / 기각 4 / 사례 3건**이다. 10분에 Phase 0~8을 다 넣으면
  아무것도 안 남는데, 이 저장소의 차별점은 기능 수가 아니라 근거이기 때문
- 대비 색은 dataviz 검증기로 확인했다 (`#4a90d9`/`#c4762c` — CVD ΔE 23.7)

## 백엔드 도메인 규칙 테스트 (10 → 29건)

**조건부 미착수가 아니라 그냥 안 한 것**이었는데 조건부 목록 옆에 섞여 있었다.
`DomainRuleTest` 19건 추가.

| 묶음 | 덮은 것 |
|---|---|
| 아이템 (6) | 등록자만 수정·삭제, **삭제는 물리 삭제가 아니라 CLOSED**, Bean Validation |
| 구매 (7) | 경매 아이템 즉시구매 거절, 본인 거래, 재고 초과, 수량 0, **재고 0 → SOLD_OUT 전이** |
| 입찰 (6) | 정가 아이템 입찰 거절, 본인 입찰, 시작가 이하, **재입찰 시 이전 입찰 OUTBID 전이** |

- **부하테스트와 겹치지 않는다.** ADR-0020이 검증한 건 동시성이고, "경매
  아이템을 즉시구매로 살 수 있는가"는 한 명만 요청해도 성립해야 하는 규칙이다
- **일부러 실패시켜 확인했다.** 본인 구매 금지와 OUTBID 전환을 각각 제거하니
  **정확히 그 2건만** 실패했다. 복원 후 `git diff`가 비었음을 확인했다
  (통과만 본 검사는 항상 통과하는 검사와 구분되지 않는다)
- **발견**: 권한 위반이 403이 아니라 **409**로 나간다.
  `InvalidTradeRequestException` 하나가 "등록자가 아님"과 "재고 부족"을 같이
  처리한다. 프론트·k6가 동시에 걸려서 별건으로 등록했고, 현재 동작은 테스트가
  고정해뒀다 — 바꾸면 실패하며 알려준다

## 트리거 점검

조건부 미착수 목록을 훑어보니 **트리거가 아닌 것이 트리거 자리에 앉아 있었다.**
"별도 측정 필요"는 작업 설명이고 "배포 전략"은 선행조건이라, 둘 다 *언제 다시
볼지*를 말해주지 않는다. 그런 항목은 아무도 안 보는 채로 남는다.

셋으로 나눴다:

| 분류 | 뜻 | 건수 |
|---|---|---|
| **관측 트리거** | 무언가 일어나면 알게 된다 | 5 |
| **선행 결정 대기** | 사람이 정해야 걸린다 | 2 |
| **하지 않기로 함** | 조건을 만들 수 없다 | 3 |

고친 것:

- `torch.set_num_threads()` — "별도 측정 필요" → **"4 OCPU 대상에 실제로 올릴 때"**.
  ADR-0028의 워커 표는 12코어에서 잰 것이라 코어가 1/3이면 초과 구독이 더 심하다
- "다른 단계 결론 전수 재검토" — **관측할 주체가 없었다.** 자동 비교 장치가 없어
  누가 우연히 눈치채야만 걸리는 조건이었다. **부하테스트를 다시 돌릴 때 같이
  확인**하는 것으로 격하했다 — 그때가 단계 시간을 어차피 보는 순간이다
- 실사용 로그 기반 재평가 3건 — **실사용자가 생길 경로가 없다.** "로그 확보 후"는
  조건이 아니라 희망이라 "하지 않기로 함"으로 옮겼다

> **"하지 않기로 함" 칸이 비어 있으면 정직한 목록이 아니다.** 영원히 안 걸릴
> 조건을 조건인 척 남겨두면 미착수가 아니라 관리 안 됨으로 읽힌다.
