# 2026-08-04 (4) — 배포 전 점검 3회차: 한도가 요청 수만 세고 있었다

3회차는 앞의 두 회차가 건드리지 않은 영역을 겨냥했다 — 아이템 CRUD 인가(IDOR),
입력 크기, 관측성, 프론트 세션.

**보안 구멍은 나오지 않았다.** 인가·격리·시크릿은 이번에도 깨끗했다. 나온 것은
**크기**에 관한 것이다.

## 깨끗했던 것부터

| 영역 | 결과 |
|---|---|
| 아이템 CRUD 인가 | `getItem(tenantId, …)` + `requireSeller` — **IDOR 없음** |
| 메트릭 카디널리티 | 라벨이 `tenant`/`intent`/`stage`/`outcome` 뿐 |
| 로그 시크릿 노출 | 백엔드·AI 모두 **0건** |
| 페이지네이션 | Spring 기본 상한 2000 적용됨 |
| CI | `./gradlew build` 가 테스트를 포함 |

## A — 한도 3계층이 전부 "요청 수"를 센다

```
19,800자 질의 → 200 OK, 16.4초
응답이 질의 전체를 그대로 되돌려준다 (≈20KB)
```

정상 질의는 ~50자 / 4.5초. **비용은 요청 수 × 요청 크기인데 뒤쪽이 자유였다.**

### 발견 단서가 같은 줄 옆에 있었다

```python
query: str                                  # 상한 없음
size: int = Field(default=10, ge=1, le=50)  # 상한 있음  ← 대조군
```

`size=999` 는 실제로 **422** 로 막힌다. **저자가 상한을 둘 줄 안다는 증거가 바로 옆에
있으므로**, 없는 쪽은 의도가 아니라 누락이다.

### 500자는 감으로 정하지 않았다

| 근거 | 값 |
|---|---|
| 임베딩 `max_seq_length` | **128토큰** |
| 리랭커 `max_length` | **256토큰** |
| LLM | **자르지 않는다** |
| 데이터셋 질의 547건 | 최소 5 · 중앙 18 · p99 31 · **최대 33자** |

256토큰 너머는 캐시·검색·리랭킹 어디에도 영향을 주지 않고 **LLM 요금만 늘린다.**
500자는 관측 최댓값의 15배라 정상 사용은 근처에도 안 간다.

## B — DB 제약이 DTO 에 반영돼 있지 않았다

컬럼은 `varchar(200)` 인데 `@Size` 가 없어서 201자가 검증을 통과하고 **INSERT 에서
터졌다.**

```
name 300자 → 500   (400 이어야 한다)
name 200자 → 201   (대조군)
```

수정 요청에도 같은 상한을 걸었다 — 등록만 막으면 같은 결함이 경로 하나로 남는다.

## C — 만료 처리가 설계에서 사라진 채로 남아 있었다

ADR-0023 설계안에 *"만료 시 재발급 후 1회 재시도"* 가 있었는데, **로그인이 진짜
비밀번호가 되면서 조용한 재발급이 불가능해졌고**(비밀번호를 들고 있지 않다)
**대체 처리가 들어가지 않았다.** TTL 1시간이라 데모 탭을 열어두면 반드시 만난다.

세션을 접고 로그인 화면으로 되돌린다. **로그인 실패의 401 과 세션 만료의 401 을
갈랐다** — 안 가르면 비밀번호를 틀릴 때마다 "세션 만료"가 뜬다. `accessToken` 유무가
그 구분이다.

## 곁들여 잡은 문서 드리프트

API 명세의 `/api/search` 절이 아직 **`tenant_code`(필수)** 라고 적고 있었다 —
ADR-0022 가 본문에서 제거한 값이다.

## 검증

| | |
|---|---|
| AI 테스트 | 125 → **137** (경계값 12건) |
| 백엔드 테스트 | 46 → **49** (길이 경계 3건) |

경계로 쟀다 — 500자는 통과, 501자는 거부, 200자는 201, 201자는 400. **"길면 막힌다"만
확인하면 상한을 하나 어긋나게 잡아도 통과한다.**

## 배운 것

> **막으려는 양과 세는 양이 다르면, 아무리 여러 겹을 쌓아도 한 축이 열려 있다.**
> 이 프로젝트는 LLM 비용을 막으려고 3계층을 쌓았는데 세 계층 모두 요청 수를 셌다.

> **같은 파일 안의 비대칭이 가장 싼 단서다.** "여기만 왜 다르지"를 먼저 본다.

## 3회차까지의 수확 곡선

| 회차 | 발견 | 성격 |
|---|---|---|
| 1 (ADR-0033) | 2건 | **보안 구멍** |
| 2 (ADR-0034) | 3건 | 진단 불가능 |
| 3 (ADR-0035) | 3건 | 비용·견고성 — **전부 fail-safe 쪽** |

보안 구멍은 1회차에서 끝났다. **4회차는 하지 않는다** — 남은 것은 실환경에서만
드러나는 종류다.
