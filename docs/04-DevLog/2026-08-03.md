# 2026-08-03 — 공개 준비 (ADR-0031)

배포 서버를 **공개**하기로 하면서 9b(ARM·실배포)보다 앞선 라운드가 생겼다.
지금 상태를 그대로 공개하면 (1) 누구나 GM 토큰을 받고 (2) LLM 호출이 내 카드로
결제된다.

## 한 것

| | |
|---|---|
| 로그인 | `demo-token` 제거 → BCrypt 비밀번호. **회원가입 없음**(의도적) |
| 비밀번호 | 저장소에 없다. 기동 시 주입, **GM 은 별도 비밀번호** |
| LLM 비용 | 3계층 — OpenAI 월 상한(사람) / 로그인 게이트 / **일일 50회** |
| XFF | 신뢰 프록시에서 온 것만. **기본값은 빈 목록** |
| 시크릿 | `prod` 에서 기본값이면 **기동 거부** |
| 배포 | nginx 80 만 공개 |

판정선 **10개 전부 통과**, 그중 **5개는 실패를 만들어** 확인했다.

## 지적으로 설계가 나아진 지점 셋

착수 전 검토에서 세 가지를 지적받아 반영했다. 전부 **검사가 무엇을 놓치는가**에
관한 것이었다.

**1. 판정 3을 양방향으로.** "일반 비밀번호로 GM 로그인 실패"만 보면 **초기화가
반대로 잘못된 경우**(ADMIN 비밀번호가 일반 계정에도 걸리는)를 못 잡는다. 역방향은
일반 계정 **4개 전부**를 돈다 — 한 계정에만 잘못 적용되는 게 실제 실수 형태다.

**2. 일일 한도의 리셋 시점.** 설계안에 빠져 있었다. 키에 KST 날짜를 넣어
"한국시간 자정"이라고 설명할 수 있게 했고, **고정 윈도우의 2배 한계를 하루
단위에서도 수용한다**고 명시했다.

**3. 판정 6은 백엔드 포트에 직접.** nginx 를 거치면 nginx 가 헤더를 덮어써
**스푸핑 시나리오 자체가 재현되지 않는다.** 그래서 포트가 열린 로컬 구성에서만
성립하고, 배포에서는 포트를 닫는 판정 9가 따로 있다 — 둘은 다른 계층이다.

## 작업 중 잡은 것 여섯 건

1. **`BadCredentialsException` 이 500 으로 나갔다.** Security 의 예외 변환은 필터
   체인 것만 다루는데 이건 서비스 안쪽에서 나온다
2. **테스트가 429 에 걸렸다.** 리미터는 정상 동작이고 테스트가 비밀번호 로직을
   재는 것이라 그 테스트에서만 껐다
3. **판정 1의 검사가 약했다.** `demo-token` 이 404 가 아니라 **401** 을 냈다 —
   보안 계층이 먼저 막기 때문이다. 숫자만 바꾸면 **인증 뒤에 되살려도 통과**한다.
   유효 토큰을 들고 가게 고쳐서 404 를 "핸들러 부재의 직접 증거"로 만들었다
4. **compose `environment` 누락 3회** — `RABBITMQ_HOST`(어제), `DEMO_PASSWORD`,
   `DB_PASSWORD`. 증상이 각각 "설정이 안 먹는다", "password authentication failed"
   라 원인이 애플리케이션 쪽으로 보인다
5. **`ports: []` 가 포트를 안 지운다.** Compose 는 시퀀스를 이어 붙인다 →
   `!override` 가 필요하다
6. **비밀번호 주입이 시드에 덮인다.** `db-seed` 가 backend healthy 뒤에 돈다
   (테이블을 Hibernate 가 만들어서 그 순서를 피할 수 없다)

## 검사가 또 두 번 틀렸다 — 하나는 새 종류

**"약했다"가 새 하위분류다**(사례 10). 앞의 아홉은 결과가 틀렸는데(오보/침묵/
동전던지기) 이건 **결과는 맞고 근거가 약하다.** 뮤테이션으로도 잘 안 잡힌다 —
엔드포인트를 지우면 401 이든 404 든 실패하므로 "잡았다"고 착각한다.
**"이 검사가 통과하는 다른 경로가 있는가"** 를 따로 물어야 한다.

그리고 **"안 뜬 것"을 "닫힌 것"으로 읽었다**(사례 11). 배포 검사가 8080 닫힘을
통과로 읽었는데 실제로는 `SecretGuard` 가 기동을 거부해 컨테이너가 안 뜬 것이었다.
포트가 닫힌 것과 프로세스가 죽은 것은 **밖에서 보면 똑같다.**

→ 스택 생존 확인을 **맨 앞**에 넣고, **"실제로 쓸 수 있는가"**(프록시 경유 로그인
200)를 맨 뒤에 넣었다. 그 하나가 결함 5·6을 동시에 잡는다.

## 공개 데모의 딜레마 — 숨기지 않고 적었다

비밀번호를 README 에 적으면 로그인 게이트의 의미가 반감된다. 그래도 적어야 접속이 된다.

**게이트의 목적은 접근 제한이 아니라 익명 대량 호출 차단**이다. 비밀번호가 알려져도
(a) 봇이 자동으로 넘지 못하고 (b) 사용자당 하루 50회가 걸린다. 진짜 방어선은
OpenAI 월 상한이고 이건 그 앞의 두 겹이다. **GM 비밀번호는 공개하지 않는다** —
그게 비밀번호를 둘로 나눈 이유다.
