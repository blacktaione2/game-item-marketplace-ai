# 2026-08-09

## LLM 모델 세대 교체 (ADR-0045)

**모델 이름에는 근거가 없었다.** ADR-0004 는 *프로바이더*를 정하지 모델을 정하지
않는다. `gpt-4o-mini` 와 `claude-sonnet-4-5` 는 초기 기본값이 한 번도 재검토되지
않은 것이었다 — 이 저장소가 반복해서 잡아낸 *"결정이 아니라 그렇게 된 것"* 이다.

### 가장 최신을 못 쓰는 이유가 측정됐다

먼저 API 에서 **실제 모델 ID** 를 받았다(마케팅 이름 "GPT-5.6 Sol" 은 ID 가
아니다). 그다음 우리 클라이언트로 `temperature=0` 을 보내봤다.

| 모델 | `temperature=0` |
|---|---|
| `gpt-5.6-sol` · `terra` · `luna`, `gpt-5.5`, `gpt-5-mini` | **거부** |
| `gpt-5.4` · `5.4-mini` · `5.4-nano` | 수용 |
| `claude-sonnet-5`, `opus-4-7`, `opus-4-8` | **거부** |
| `claude-sonnet-4-6` · `4-5` · `haiku-4-5` | 수용 |

추론 내장 세대가 온도를 1로 고정한다. 쓰면 **ADR-0017 이 세운 결정성이 통째로
무너진다.** 그래서 답은 취향이 아니라 제약이고, 이제 한 줄짜리 검사로 남았다.

날짜도 고정했다 — 부동 별칭이 ADR-0043 에서 실제로 진단을 막았다.

### 하네스 재측정 — 대조군을 같은 날 함께

기록값과 비교하지 않았다. 옛 모델도 부동 별칭이라 드리프트했을 수 있다.

**재작성 결정성**: gpt-4o-mini 토큰집합 1.000/1.000(0-in-10) vs
gpt-5.4-mini 0.950/0.920(3-in-10). **새 모델이 덜 결정적이다.**

**그런데 검색 결과는 동일했다** — 재작성 문구도 리랭커 점수도 움직였는데
**적합 20 / 부적합 14 가 양쪽 같고** 0건 질의도 같은 1건이었다.

> **결정성은 목적이 아니라 결과를 지키는 수단이었다.** 수단이 흔들려도 결과가
> 안 흔들리면 대가가 아니다. 이걸 안 재고 기각했다면 **잴 수 있는 것을 안 재고
> 기각**하는 셈이었다.

**원소 추출**: 111/117 → **117/117**, 사전 등록 기준 **5개 전부 PASS**(전엔 2 FAIL).
ADR-0040 이 미해결로 남긴 둘(`"속성 안 붙은 신발"`·`"어둠 속성 로브"`)이 닫혔다.
대신 **부정형에 스스로 `무속성` 을 채우는** 새 결함이 생겨, 채우기만 하던
후처리를 **지우기까지** 확장했다(`무속성` 일 때만 — 다른 속성 불가침).
재채점은 수집/채점 분리 덕에 **API 0회**였다.

**도메인 게이트만 애매하다**: 미검출 V1 2/38 → **0/38**(개선), 오거부 전체
0.79% → 2.55%(악화). **일반 질의 141건은 양쪽 다 0**이고 경계는 n=32 라 95%
구간이 겹쳐 구분되지 않는다.

> **한 모델에 맞춘 프롬프트는 옮겨가지 않는다.** ADR-0039 가 다섯 번 반복해
> 다듬은 그 문구는 `gpt-4o-mini` 의 읽기에 맞춘 것이다. 다시 다듬는 건
> held-out 을 한 번 더 태우는 일이라 별개 라운드다.

지연 **2403ms → 약 800ms**(3배).

### 그 과정에서 고친 것 둘

- **`ai/.env` 가 코드 기본값을 덮는다.** 실제로 `anthropic_model` 만 바뀌고
  `openai_model` 은 안 바뀌었다 — `.env` 에 전자는 없고 후자는 있었다.
  **배포 서버의 `ai/.env` 도 같이 바꿔야 한다**
- **하네스 11개가 Windows 에서 죽고 있었다.** `print()` 안의 em dash 가 cp949
  콘솔에서 `UnicodeEncodeError` 를 낸다. 표는 다 나온 뒤라 결과는 안 잃지만
  **exit 1 이라 자동화가 실패로 읽는다.** 이번에 두 스크립트가 그렇게 죽었다

테스트 292 → **296**.

## 같은 날 (2) — 배포했는데 모델이 안 바뀌었다

`git pull` → 재빌드 → 재시작까지 정상이었는데 **옛 모델이 그대로 돌고 있었다.**
증거는 그 출력 안에 있었다:

```
2:OPENAI_MODEL=gpt-4o-mini      <- 서버 ai/.env 가 여전히 옛 값
```

내가 준 절차가 `grep` 으로 확인하라고만 하고 **사람이 읽고 판단하게** 뒀다.
grep 은 제 일을 했다 — 옛 값을 정확히 찾아냈다. 그런데 그 다음 줄에서 재빌드가
그대로 진행됐다.

> **읽고 판단해야 하는 확인 절차는 놓친다.** 특히 그 줄이 긴 출력 한가운데
> 있으면 더 그렇다. 이 저장소가 배포에서 세 번째로 겪는 "성공했는데 안 바뀐다"다
> (푸시 누락 → `cache_version` → 이번).

`/health` 에 **`llm_model`** 을 실었다. 이제 한 줄로 확인된다.

```bash
docker exec gimp-ai python -c "import urllib.request,json;print(json.load(urllib.request.urlopen('http://localhost:8000/health'))['llm_model'])"
```

`llm_fallback` 을 여기 실은 이유(로그 레벨이 막혀 안 보였다)와 **같은 자리에
같은 이유로** 하나가 더 붙은 셈이다 — *판정에 쓸 값이 관측 가능해야 한다.*

`tests/test_health_payload.py` 가 **양방향**으로 고정한다: 실을 것이 실리는지와
**비밀이 안 실리는지**. 후자만 두면 "본문이 비어서" 통과하므로 공허함 방지
검사를 같이 넣었다. 배포 절차의 판정 표에도 `llm_model` 줄을 넣었다.

테스트 296 → **301**.

## 같은 날 (3) — 내가 준 대기가 무한 루프였다

모델 교체를 확인하려고 넣은 대기에서 화면이 멈췄다.

```bash
until [ "$(curl ... http://localhost/api/backend/health)" = "200" ]; do sleep 3; done
```

**`localhost:80` 은 `gimp-web` 이 아니다.** 이 박스는 공유라 80 은 호스트
nginx(TLS 종단)가 잡고 있고 `gimp-web` 은 다른 포트에 게시된다 — 앞서 SSE 검증에서
`WEB=http://localhost:8081` 을 쓴 게 그 증거였는데 옮기지 않았다.

`verify-deploy.sh` 는 머리말에 *"호스트를 우리가 독점한다는 가정"* 이 틀렸다고
적어두고 **그래서 포트를 두드리지 않고 Docker 에 묻는다.** 나는 그걸 안내문에
반영하지 않았다.

게다가 그 대기에는 **출력도 타임아웃도 없었다.** 조용한 대기는 "멈췄다" 와
구분되지 않는다.

고쳤다 — 주소를 `docker port gimp-web 80` 으로 얻고, 비면 크게 경고하고,
회차마다 상태 코드를 찍고 120초에서 포기한다. 문법과 실패 경로를 실제로 돌려
확인했다(대상 없음 → 경고 + `000` 이 매 회차 찍힌다).

> **이 라운드에서 내가 준 대기 조건이 세 번 연속 틀렸다** — `/`(백엔드를 안 거침)
> → `localhost/api/...`(남의 nginx) → 출력·상한 없음.
> **안내문은 검사보다 덜 검증된다.** 검사와 달리 돌려볼 대상이 없어서다. 그래서
> 절차 문서 안에 넣고 실제로 실행해봤다.

## 같은 날 (4) — 확인 명령이 문서가 이미 404 라고 적어둔 경로를 찔렀다

포트를 고쳐 다시 물었더니 `{"detail":"Not Found"}`. nginx 는 `/api/ai/` 를
`ai:8000/api/` 로 보내는데 **AI 헬스는 `/health`**(접두사 없음)라 프록시로는
닿지 않는다.

**그 사실이 이미 세 곳에 있었다** — `API-명세.md` 187행이 *"경유로는
`/api/ai/health` 가 404다"* 라고 적어뒀고(나는 **같은 파일 619행에** 그걸
반박하는 curl 을 넣었다), `CLAUDE.md` 가 `verify-container.sh` 의 첫 판본이 404
경로를 찔러 통과한 사건을 기록했고, `배포-절차.md` 는 **두 줄 위에 맞는 명령**을
갖고 있었다.

맞는 확인:

```bash
docker exec gimp-ai python -c "import urllib.request,json;print(json.load(urllib.request.urlopen('http://localhost:8000/health'))['llm_model'])"
```

> **이 라운드 배포 오류 다섯 중 넷은 답이 바로 위·아래 줄에 있었다** —
> `CACHED` 로그, 3-a 의 재시작 이유, `verify-deploy.sh` 의 "호스트를 독점하지
> 않는다", 그리고 이번의 `docker exec` 줄. 앞선 라운드들의 교훈이
> *"판정에 쓸 신호가 도달하는지 확인하지 않았다"* 였다면, 이번은
> **"이미 적혀 있는 것을 안 읽었다"** 다.

## 같은 날 (5) — 마감 전수 점검

모델 교체로 **낡아진 수치**를 훑었다. 가장 위험한 건 `CLAUDE.md` 였다 — 그 파일이
`gpt-4o-mini` 기준 숫자를 **현재 사실로** 적고 있어서, 다음 작업이 그걸 믿으면
틀린 전제로 시작한다.

| `CLAUDE.md` 무속성 | "42/50 틀린다" → **역사로 읽으라**고 명시. 지금은 42/42, 후처리는 지우기가 값을 한다 |
